# 拾语：数据与学习指标技术方案 v0.1

2026-11-11，数据建设/学习测量角色工作稿。依据已认可的 v0.11 原型、R01—R33需求及架构评审。只设计，不建库、不写业务代码、不调用评测或分析服务；AI Agent负责研发，用户决策和人工验收。学习效果、供应商和指标阈值均未实测。

## 1. 初期方案与数据归属

建议PostgreSQL保存业务事实、事件和小规模看板投影，原件/录音/视频放私有对象存储。暂不引入数仓、Kafka或独立实时计算平台；数据增量和重建任务由受控Worker执行。各Module只写自己的表，数据建设通过Interface/已提交领域事件读取，不用看板反写学习状态，也不通过埋点结算费用。

| 数据域/主责 | 必要记录与字段（概念设计，不是DDL） |
| --- | --- |
| 账号权限/后端 | owner_id、space_id、device_id、授权/撤权版本、访问策略；客户端不能自报一个owner就取得归属 |
| 材料内容/后端 | material_id、material_version、learning_version、unit_id、sentence_id、原件页码/时间锚点、来源与修订关系 |
| 媒体评测/后端 | media_version、alignment_version、audio_start/end、原始录音引用、task_type、quality_status、provider/model/评分规则版本、有效维度及缺失原因 |
| 会话/学习Module | session_id、attempt_id、题目/题目版本、作答条件、播放与开口区间、回答引用、接受判定及判定版本 |
| 词句复习/复习Module | entry_id、原形/词形、词义或短语、个人原句引用；维度状态、due_at、历史attempt、调度版本与原因 |
| 投影/数据Module | user_daily_activity、dimension_summary、assessment_series；metrics_definition_version、watermark、computed_at、样本数/排除原因 |

接收投递ID、任务尝试、预算预留和实耗账本由后端拥有。看板费用只读该权威账本，不从播放事件、回调次数或点击“重试”推算扣费。学习材料修改生成新版本；旧词句与成绩仍指向旧版本，无可靠句子映射时不按百分比迁移。R07/R08/R10/R30为关键依赖。

## 2. 事件契约与可靠性

采用至少一次投递：业务提交与Outbox同事务；数据消费者按event_id去重，投影更新和消费回执一起提交。客户端补传保留原event_id，另以device_id＋session_id＋device_sequence识别重复，不为每次网络重传生成新学习事实。

最小事件字典：

| 事件 | 内容/用途 |
| --- | --- |
| playback.interval_recorded | 墙钟与单调时钟区间、媒体位置起止、速度/跳转/缓冲/中断；拆出真正播放区间 |
| lookup.opened / entry.saved | 查询词句与来源引用；手动保存建立复习条目，查询或收藏不等于掌握 |
| assistance.used | 题目文字、中文、慢放、关键词、示范及发生顺序；选项试听另记，不能和“看了答案”混同 |
| answer.submitted / answer.evaluated | attempt、题目版本、回答引用、判定者/规则版本、多可接受答案集合引用；服务失败不记错误答案 |
| speech.interval_recorded / assessment.completed | 有声区间、录制条件、质量与专业结果引用；不能以ASR文本重合率生成声学分 |
| review.scheduled / publication.withdrawn / asset.deletion_requested | 调度原因；停止源内容访问；投影和制品清理，不携原文或录音 |

契约示例（字段示意）：

```json
{
  "event_id": "evt-example", "schema_version": 1,
  "event_type": "answer.evaluated", "owner_id": "server-bound-user",
  "device_id": "device-example", "session_id": "session-example",
  "attempt_id": "attempt-example", "occurred_at": "client-time",
  "received_at": "server-time", "device_sequence": 8,
  "material_id": "material-example", "learning_version": 2,
  "unit_id": "unit-example", "sentence_id": "sentence-example",
  "question_id": "question-example", "question_version": 3,
  "dimension": "listening_response_selection",
  "assistance": ["question_text"], "question_replays": 2,
  "evaluation_status": "accepted", "evaluation_version": "policy-example"
}
```

事件默认不带全文、录音、访问密钥或自由回答正文；需要回看时凭受权引用获取。标识符仍可关联个人，不能声称匿名。归属与服务端结果由认证上下文产生；客户端行为有source/confidence标识，不能宣称所有遥测都可证明真实学习。

晚到事件更新其实际发生日期的投影，并展示更新时间。离线区间使用单调时钟时长＋设备时间映射核查；时钟漂移、逆序或不可能区间先隔离为“待核查”，不任意算零或强行补满。破坏性schema开新版本，旧事件保留兼容读取。重建在新projection_version下完成再切读，删除标记必须参与回放，禁止复活已删除内容。

## 3. 指标：活动与能力分开

| 指标 | 建议定义/限制 |
| --- | --- |
| 收听分钟 | 实际播放墙钟区间的并集；排除缓冲、暂停、seek跨过部分。0.8倍不按媒体秒当真实投入，播放完不等于听懂 |
| 练习分钟 | 练习任务内可观察的有效活动区间；空闲截断规则须验证，纯阅读不能假装精确测出注意力 |
| 主动开口分钟 | 实际人声区间的并集，剔除无声/示范音；噪声误检与VAD门槛待设备样本校准 |
| 听辨/接话 | 分母仅为该题型已完成、可判定attempt；独立和含文字/中文/慢放等条件分别呈现，选择正确不证明自由会说 |
| 词义回忆、拼写、运用 | 独立维度；拼写可选，不做即无样本，不是退步。使用词义和场景是否恰当，不只匹配指定单词 |
| 提示依赖 | 按题型、帮助种类统计使用量及attempt占比；不能把“示范回答后复述”记作自主表达 |
| 专业发音趋势 | 仅纳入质量合格、服务有效结果；保存provider/model/评分规则、朗读/关键词/自由回答、题目难度及录音条件 |

同人多设备重叠播放只计一次墙钟时间；会话记录分别保留。开口与练习可能重叠，展示为包含关系，不能把三项相加包装成总学习时长；如需总投入，使用全部有效区间的并集。已到达的重复区间不反复计数，跨午夜切分日期。

发音对比须同评测版本/任务条件，并用固定锚句或经定义的相似难度样本；仅“同供应商”仍不足。模型更换分系列展示，不直接续线。无声、过短、噪声大或服务失败显示未评测/不足原因。数值是专业服务的指标分，不擅改称“82%发音准确率”。最小样本数、质量线、重测稳定性与人工/参考样本一致性门槛，须在获授权验证前写进协议，当前不虚构百分比。

## 4. 可解释的复习调度

先用简单、可回放的规则：手动收藏形成候选，答错/提示后成功/独立成功分开；下一轮选择近期困难句与到期词句的小组，按遗忘风险、本人目标和可用时间排序。间隔依据延迟独立检索表现逐步延长；即时看答案后重做正确不升级长期掌握。初始间隔仅候选配置，非已证明最佳算法。

每次调度保留rule_version、输入attempt、due_at、reason；允许暂停、减量、跳过和结束。容量上限不等于删除超量词，延期条目保留并重新排程，不显示必须清零的欠账。难度轮换加入同场景新变体；隔天/数日后分别看回忆、理解与减少提示的表达，避免熟题刷分。自由回应允许多合理表达，评价不确定时不强判会用，也不以关键词命中代替沟通成功。

## 5. 隐私、质量与验收

- 私有记录、作品草稿和发布快照分开；作者撤回内容阻止后续授权读取，不误删朋友自己的独立学习成绩。保留成绩不等于可继续读取被撤回原文；展示内容引用失效状态。具体保存期限与删除范围待产品决议，不默许永久保存。
- 导出/删除由各Module所有者执行；数据侧清理投影、排程及个人事件范围并出回执。删除墓碑只保留必要去重/防回放标识，最小字段和保留期另定；备份过期及外部副本不能承诺即时全清。
- 契约验收：同事件重放不增计；晚到和乱序最终投影一致；多设备重叠分钟不翻倍；换学习版本不指错句；提示后答对不混入独立通过；无样本不画下降；服务失败不记零分；删除后重建不复活；跨账号读取拒绝。
- 数据质量报告核对版本锚点缺失、孤立引用、未判定attempt、异常区间、事件积压/投影滞后和指标分母；问题须可追溯到脱敏ID。每日任务/审计尚未创建。

本方案主要覆盖R02、R10—R19、R25—R27、R30/R33。先与客户端/后端统一事件和版本契约，再在需求评审中冻结指标；未冻结前看板不能把候选统计包装为能力结论。
