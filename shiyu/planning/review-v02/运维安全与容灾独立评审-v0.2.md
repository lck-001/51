# 拾语：运维、安全与容灾独立评审 v0.2

2026-11-11。评审角色：Codex SRE／安全／发布架构师。依据planning内架构、后端、客户端、数据、测试和产品方案；本轮只做文档和官方资料核对，未部署、未压测、未外发样本、未调用付费服务。AI Agent研发、用户人工验收已确认，但没有证据证明存在真人值班、四端设备或生产账号。

## 1. 结论

**主技术路线可保留，运维设计须补充后才能放行生产。** 模块化核心、独立Worker、PostgreSQL和私有对象存储能够形成分阶段演进路径；这不证明当前吞吐、可用性或语音效果。官方资料证明这些组件仍有维护与部署能力，不能据此宣布组合是“当前最主流”或市场第一。

现稿已正确描述未知结果、取消、预算与私有隔离，但缺少实际运行所需的拓扑、恢复目标、发布契约、限额和处置责任。下文P0指对应里程碑前必须关闭，不禁止继续原型/方案，也不等于此刻必须采购所有基础设施。

## 2. 推荐最小可运维拓扑与扩容路径

| 阶段 | 候选部署 | 主要剩余风险/升级条件 |
| --- | --- | --- |
| 本人受控验证 | TLS入口；API独立进程；解析/语言/媒体/评测各独立执行进程与资源限额；PG；私有对象存储；独立保存备份/告警 | 可以共宿主降低验证成本，但宿主、磁盘、数据库及网络仍是共同故障域；多进程不等于多节点HA。必须声明维护中断，具备恢复记录后才托管唯一学习资产 |
| 受邀灰度 | API与重媒体Worker可分主机；优先评估托管PG与对象存储；PG仅私网访问；备份与生产凭据隔离；构建/预发与生产隔离 | 托管与自建按预算/运维能力比较，不默认已购买。API加副本前先确认状态外置、全局准入和滚动兼容；用户/供应商配额未解时加Worker可能只增加成本 |
| 公开服务 | 按批准SLO选择跨故障域API、数据库故障转移、独立媒体资源池与分区容量；受控媒体交付层/CDN；恢复演练 | 需要真正的副本、故障检测、切换与重连证据才称HA；复制不是备份。多地域双活不作为首版默认工程 |

初期使用受支持的进程管理器或容器编排即可，不强塞Kubernetes和全面微服务。进程启动/重启、健康检查、停止接新与排空必须写入部署定义；API健康不等于整条语音生成链健康。CPU密集解析/FFmpeg不能阻塞HTTP事件循环。FastAPI多Worker各有内存与连接池，进程数增加须同时核算总RAM和PG连接数。[S1]

“Module互不影响”不能成立：同库锁/事务、连接池、磁盘、对象存储、网关、授权、计费及发布缺陷仍可扩散。目标应改成故障限制在受控资源池、已生成内容尽量可读、权限和费用拒绝失效时仍安全。

## 3. P0：首次真实用户灰度前必须闭环

| 风险/现有缺口 | 必须补入方案的决策 | 验收证据 |
| --- | --- | --- |
| 没有恢复目标与演练 | 每类资产分别确定可接受丢失窗口RPO、恢复时长RTO，写明目标待批准、实际待演练；PG基线备份+连续WAL、对象版本/保留、配置与密钥恢复各有归属 | 在隔离恢复环境恢复至选定时点，核对数据库引用、对象清单、密钥可读性、账本及删除标记；不能只提供“备份成功”截图 |
| 灾备恢复会重发付费任务 | 恢复先关闭新外部执行，核对未终态attempt、供应商请求ID/实际账单、预留和Outbox；结果未知挂起，不把恢复后的queued直接全跑 | 模拟外部调用已完成但本地状态尚未落库，恢复后不盲重发、不重复记账；记录无法判定时的人工核查路径 |
| 备份把撤权/删除状态回退 | PG快照、对象版本、删除/撤权记录与恢复时间不一定同步；恢复后先重放有效生命周期决定并重新核验分享/Agent准入 | 已删除内容不因恢复/投影重建复活；已撤回分享不会重新开放；保留必要审计与删除政策，不承诺备份即时逐字节清除 |
| 无全局供应商准入和成本故障保护 | 账号预算之外增加每供应商/模型/地域全局并发、请求速率、音频时长/token限制、排队上限和公平性；跨进程共享权威准入，考虑429、价格变更、挂起预留 | 多API/Worker实例并发不会各自放大配额；额度或权限不明不发新付费步骤；熔断后旧结果可读，未知费用不自动当零释放 |
| 单靠URL过期宣称可撤回 | 明确媒体交付是授权代理还是短凭据/CDN；校验Range请求、缓存键、跨用户缓存隔离和撤回窗口，签名URL不进入日志 | 两账号与已撤回版本测试；新的未授权请求拒绝；已经开始的下载/已缓存字节不能保证立即回收，产品文案不承诺强制消失。[S4] |
| 发布和数据库回退不兼容 | 建立API/事件/数据版本兼容窗口，迁移先expand、应用双读/兼容、稳定后contract；数据迁移独立执行，不由每个API副本启动时各跑一次 | 老客户端/旧Worker仍可处理兼容数据；灰度回退代码不损坏新字段/账本；破坏性迁移有前向修复或经批准恢复计划，不用简单降版本冒充数据库回滚 |
| AI角色不能值班处置 | 明确谁接报警、何时可响应、谁批准停付费执行/对外通告/恢复；无人响应窗口用有限开放与更保守自动保护 | 报警可送达并演练处置；没有真人接管不能承诺全天候有人值守或固定SLA。AI不能自行采购、越权公开数据或无限重试 |

PG PITR依赖可用基线备份和连续WAL，逻辑dump不能替代这条恢复链；它也不会自动恢复对象存储、供应商执行历史、配置文件或访问密钥。[S2] 数据库恢复“成功”并不等于整个产品已经业务一致。

## 4. SLO、监控与可操作报警

先定义测量与失效分支，再按试用期测量商定数值，不在无负载数据时编造99.9%或固定并发量。

| 用户承诺/目标候选 | 必测指标 | 对应动作 |
| --- | --- | --- |
| 已生成内容能继续听读 | API可用性/延迟分位、鉴权错误、媒体首字节与Range失败、客户端崩溃与播放失败 | 读路径保护、暂停非必要生成、按构建/平台定位 |
| 处理任务可解释地完成 | 各队列最老任务年龄/等待与处理耗时、成功/部分成功/未知、租约冲突、重试次数、供应商429/5xx | 限流、停止新派发、核查未知；不是一律扩API副本 |
| 预算与资产不失控 | 预留/实耗差异、未知金额/次数、每账号及全局支出速率、对象增长与出网、临时文件及磁盘余量 | 禁止新增付费步骤、降低并发/长度、清理已确认可清内容，保留账本与原始证据 |
| 存储可恢复 | PG连接/锁等待/慢查询/WAL归档延迟、备份年龄与演练结果、对象缺失/校验失败 | 连接池保护、停写或停派发策略、恢复Runbook |
| 看板可信 | Outbox积压、投影watermark/滞后、异常区间/丢锚点/重复与隔离事件 | 展示数据暂未同步；不阻塞核心学习或用迟到投影做核权 |

关联标识：request_id、job/step/attempt、脱敏用户/资源ID、端构建、依赖版本与供应商请求引用。不能把原文、音频、认证头、提示词全文、签名URL查询串或令牌放进通用日志、trace、crash附件和高基数指标。遥测采集端先最小化，再做服务端过滤、限保留、访问审计；不能只靠看板脱敏。OpenTelemetry官方明确要求识别并处理遥测中的敏感信息。[S3]

## 5. P1：容量、成本与安全补充

- **容量模型**：分别估入站文件字节、解析CPU/内存峰值、音频分钟、视频渲染时长、供应商并发、出网速率及备份保留。Worker数受处理率/排队目标和供应商配额双重限制；API内存和连接池按副本总量核算。对象出网与媒体代理可能比API计算更贵，成本预算不能只数模型token。
- **扩容触发**：记录“等待时间持续偏离约定目标＋资源/依赖饱和”的原因，再决定扩对应Worker、拆宿主、增API、优化PG索引/轮询或换投递层。读副本/统计副本存在延迟，不用于预算、撤回或来源授权的最终准入。并非用户数到某个整数就必须分片。
- **密钥与供应链**：使用受控密钥存储或最小权限运行身份，服务端供应商密钥不下发四端。区分短期会话、Agent投递凭据、供应商密钥和苹果/Windows签名材料；需要轮换/吊销/过渡双密钥与泄漏处置记录。CI按锁定依赖、构建出处、漏洞扫描和发布制品校验维护，Agent不能自动信任下载的任意脚本。
- **恶意文件/链接**：校验真实格式、展开量、页数/时长，限制解码CPU/内存/临时盘；解析器无宏执行、无核心凭据、默认无出网。SSRF需在DNS解析和每次重定向复核，隔离内网/元数据地址，限制响应大小与时长。对象存储隔离区、未完成分块上传清理、恶意样本隔离和可审计恢复均需方案。
- **上传内容也是不可信指令**：文档/网页里的“忽略规则、读取其他来源、发布、删文件”等不能变成Agent执行许可。生成/分析模型只取得已授权输入，工具操作仍经过服务端准入；不能靠提示词代替权限。
- **媒体与渠道**：限制下载/并行Range/转码并发，防止小请求放大出网。CDN共享缓存不得混入私人原件/成绩；媒体转交与回源需保留版本、授权和可追踪失效策略。公开发现开放前再补举报、下架、滥用/机器人和作者权利处理，不要求首版强做社交系统。
- **许可证和商业权利**：建立依赖/制品清单，分别核对Flutter原生插件、FFmpeg编译选项与链接方式、编解码器、模型权重、OCR/词典数据、TTS音色、字体、背景音乐和用户公开素材授权。FFmpeg默认LGPL但可选部分引入GPL，不能只看项目名就认定任何二进制都可同条件分发。[S5] 具体使用方式与地域的许可/专利判断另核实，不宣称一个开源许可证自动涵盖全部权利。
- **客户端升级**：四端商店/测试分发、签名与公证、隐私权限文案、系统最低版本、旧协议兼容和本地缓存schema迁移都要列入发布清单；桌面能回退不代表已装手机版本即时回退。服务端功能开关控制新执行，老版本仍可读历史成果。
- **反馈与事件**：客服入口关联脱敏资源/任务标识与用户主动附加的日志范围，不默认收集完整工作材料/人声。区分误判纠音、收费异议、隐私请求和故障，设责任人和关闭证据。AI生成的运维建议需经权限控制，不能让Agent在事故中无限扩容/购买额度。

## 6. 最小Runbook表

| 事故 | 首先保护 | 核查/恢复路径 | 退出条件 |
| --- | --- | --- | --- |
| 供应商超时/429/计费异常 | 停相关Adapter新提交，保留已有内容读取 | 查attempt与请求ID/回调/账单，不自动重提未知 | 状态与费用可对账，限额/重试策略验证后限量恢复 |
| PG/宿主故障 | 停新任务与外部提交，隔离重复Worker | 切换或恢复、核对租约/账本/Outbox，供应商实际结果先核查 | 无双主/重复提交，数据及对象引用检查通过 |
| 对象缺失/存储误删 | 阻止依赖缺失对象的新处理，不伪装生成成功 | 按不可变对象版本/清单恢复，缺失项显式标记 | 原始引用可校验，删除/撤回决定未被复活 |
| 私有泄漏/密钥泄漏 | 停受影响分享/接口/凭据，保留最小审计 | 吊销/轮换、查访问范围、按既定通知责任处置 | 修复复测与授权策略通过，由责任人决定恢复 |
| 发版异常 | 关闭新功能/队列新派发，保留旧版读路径 | 回退兼容应用或前向修复；迁移不盲降schema | 老新客户端均能读必要资产，账本与任务无悬挂 |
| Worker磁盘/内存耗尽 | 限制新接单和并发，不删活跃任务文件 | 核查临时盘/失败残留/生命周期，只清已确认可清项 | 资源回到约定安全余量并验证重入，不全量重跑 |

## 7. 放行条件与未验证项

技术方案可进入修订版评审；首次灰度之前至少需要：部署与资源限额清单、实际服务/设备/签名条件、恢复目标与一轮隔离恢复证据、可送达报警与处置责任、全局配额和预算故障验证、旧客户端/迁移兼容用例、依赖及内容权利清单。正式公开还需对应SLO、隐私/滥用治理、容量成本与故障转移验收。未授权外发、跨账号泄漏、预算失控、恢复重复付费、核心数据丢失或无效录音伪分，应停止相关路径/灰度，而非为了继续上线关闭核心专业纠音。

没有实测前，不给吞吐、恢复分钟数、固定机器配置或人民币报价；可以列需求公式和待测范围。技术“可扩展”只表示存在明确演进路径，不表示扩容不改架构、不需维护或“各模块互不影响”。

- [S5 FFmpeg许可与法律说明](https://ffmpeg.org/legal.html)。本轮搜索命中官方许可摘要，正文直接打开超时；LGPL/GPL选项须按实际构建再核对，未审计任何具体二进制。
