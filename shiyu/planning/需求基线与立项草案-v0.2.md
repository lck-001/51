# 拾语：需求基线与立项草案 v0.2

日期：2026-11-11。产品经理工作稿。用户已认可v0.11原型方向并同意外部Agent＋受控学习教练增量；本版对应新增的v0.12待审画面。用户尚未逐屏验收新画面，本稿不把功能同意或静态图解释为业务开发、供应商调用或上线许可。

## 1. 本轮立项对象

帮助用户将自己选择的中文或英文内容，转成保留原意、适合自身水平的英语听说练习，逐渐减少提示，能够在相关场景听懂并回应。

输入可以是故事、演讲稿、技能说明、工作总结或外部助手整理的昨日回顾与今日计划；不卖课程或学习包，不限定职场材料。练习时长由用户自主选择，不预设每日任务量。学习效果不能由播放时长、收藏量或选对一道题代替。

立项建议先验证“私有材料→听读查词→专业发音反馈→听说复习→自己表达→看到变化”主线。保留四端和多格式完整目标，采用有验收依据的交付顺序；本稿推荐的分期尚需产品评审决议，不能当作已冻结删减范围。

## 2. 基线与变更规则

- 当前评审画面：`prototypes-v12/manifest.json`、`index.html`、`design-notes.md`，35张手机与3张桌面画布；新增Agent画面待用户审阅。
- 当前布局：学习｜材料｜＋添加｜分享｜我的。加号只添加学习材料：上传文件、粘贴内容、说一段。录像在分享页，学习内可进入同一录制模块。
- 听读页最新顺序：**正文→时间进度/播放控制→练习按钮→最底部词卡**。词卡默认两行，上拉展开例句，按钮始终在词卡上方；不能恢复 v0.9/v0.10 的旧顺序。
- 默认复习：词句填空选择、音频问答选回应、自己回答；选项可试听，题型可按本轮目标抽取，不强制固定三连。拼写只在词句本作可选专项。
- 原型数字、价格占位、评分和已连接状态均为示例。静态画布不是运行结果或逐设备支持证据。
- 后续需求变化使用需求ID记录原因、受影响画面/契约、验收和成本，不直接覆盖旧决议。历史原型保留作版本证据，不作为并列现行基线。

## 3. 必须保留的范围

| 范围 | 需求约束 |
| --- | --- |
| 四端 | Android、iPhone/iOS、Windows、macOS，每端可上传文件、继续学习；媒体和系统分享能力分别验证 |
| 自选材料 | 优先文档/PPT/Word/PDF，其次文字、截图照片、链接、录音、音视频；长材料在应用内建议分学习单元，用户可调整，不承诺无限格式/大小 |
| 内容与英语 | 提取疑点可核查；忠实/适级表达有对照，数字、名字、观点与笑点不静默改动；英语上、中文下，地道美式表达 |
| 音视频 | 材料生成音频/字幕视频；用户可录音或真人录像，权限由用户动作触发，私有草稿先保存 |
| 听读与查词 | 歌词式跟随、句级定位、语速、循环、时间进度；正文与词卡分区滚动，音标/发音/本句释义/例句/手动收藏 |
| 发音与表达 | 专业声学评测，音质不足不出确定分；照稿、关键词和自由表达条件分开，不用ASR文本相似度充当发音准确率 |
| 复习与进步 | 先尝试再揭示，答错回原句，延迟检索；听辨、回忆、拼写、运用分开记录；提示依赖、可比发音和前后录音可查看 |
| Agent | 外部助手送入优先验证，显示接收账号、来源、版本、投递与任务状态；平台代理仅在明确来源/时间/范围授权后读取 |
| 私有与分享 | 材料默认私有；私人学习记录、作品草稿、固定发布版本分开；原件与成绩另选，不因分享作品自动公开 |
| 用量与资产 | ASR/OCR等外部处理也需事先确认范围/估算/上限；任务结果未知先核查；支持资产导出、删除及明确回执 |

| 验证批次 | 建议内容 | 不代表什么 |

## 6. 角色、输入和责任

产品负责需求ID、场景、阶段范围与验收；前端负责四端文件/媒体/权限、两行底词卡与自适应、同步交互；后端负责账号隔离、版本、任务/计费/权限和外部Agent入口；数据负责学习事件、指标可比性、复习调度与导出删除数据范围；测试负责需求覆盖、四端实机与失败用例；架构师统一模块归属、Interface、Adapter、任务与事件契约。一个问题必须有主责，AI角色不等于真人排班或已具备设备。

用户已确认首轮主要由AI Agent开发，用户负责产品决策和人工验收。各端方案因此优先考虑AI可维护、四端复用、契约清楚和可重复验证，不再把“是否有真人团队”列为待决策。Mac构建/签名环境、iPhone等真实设备、开发者账号和试用样本仍是后续具体依赖，不能假设已经提供。

## 7. 成功验证与立项决议项

产品价值假设：用户能独立把自己的材料变成可用练习；隔天和数日后对相似场景减少提示仍能理解/回应；第二周愿意主动带新材料回来。试用计划须分别测行为和能力，不能提前写提升比例或市场留存结论。

本阶段最多三组待决定事项：

1. **阶段范围与设备**：确认V1/V2合批关系，以及四端设备、Mac构建/签名环境和发布账号可用性，之后才估可承诺的日历排期；开发以AI Agent为主、用户决策与人工验收已确认。
2. **技术路线**：各端/架构方案比较后，选定客户端路线、后端部署与数据区域；不从原型HTML推断必须用Web实现。
3. **效果验证授权**：明确服务、样本、外发数据、保存规则与费用上限，授权后才调用，不以“先看效果”自动启用收费服务。

三组待决策不阻塞本轮产品与各端方案写作。当前立项草案待形成决议，开发门禁未通过。
