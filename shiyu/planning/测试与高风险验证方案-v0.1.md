# 拾语：测试与高风险验证方案 v0.1

日期：2026-11-11。状态：方案草案，供立项、需求和技术联评。本轮只阅读现有设计与方案，未编写测试代码、调用服务、外发样本或执行设备验证，不存在通过率、实耗或测试通过结论。

依据：《需求基线与立项草案-v0.1》《四端客户端技术方案-v0.1》《架构测试落地评审-v0.8》。画面基线为 v0.11。用户已确认主要由 AI Agent 研发、本人做产品决策和人工验收；这不代表四端设备、Mac 构建签名、语音供应商或真人英语审阅资源已经具备。

| 验收层 | 检查对象 | 所需证据与责任 |
| --- | --- | --- |

| 集成 | 导入→生成→听读→复习、任务恢复、数据投影 | 获准实现后保留构建版本、环境、请求/任务关联标识、预期与实际、缺陷复测；替身服务只证明平台行为 |
| 真机 | 四端上传、音视频、权限、蓝牙、后台、中断 | 每端真实设备/OS/构建/外设与录屏或经脱敏日志；模拟器结果单列，不能替代全部真机结论 |

## 3. 五类高风险验证包（均尚未执行）

### A．专业纠音与自由表达

- 样本分照稿、关键词、自由回应；含安静、噪声、无声、过短、重复录制及服务不可用。任务类型、帮助条件、录音质量、服务/模型/评测版本和评分维度必记。
- 对同一样本重测稳定性、目标问题定位及示范是否有帮助做对照；改变模型/任务条件不直接连成提升曲线。仅 ASR 转写相似度不能通过此验证。
- 无效样本按所选服务和预先约定的质量规则拒评，或明示不足；不得自动补满维度。自由表达判断是否回应且意思清楚，不与唯一参考答案逐字匹配。
- 通过口径：反馈可解释、无效样本不伪分、任务支持范围可追溯；数值稳定性和审阅一致性目标在选服务与样本后、执行前约定。小样本只能发现问题，不能证明总体准确率或学习提升。

### B．多格式保真、题目与逐句对齐

- 使用自造或明确许可的 Word/PPT/PDF、扫描/截图、多栏/表格、长短文、术语和故事，后续按输入优先级覆盖录音/音视频。每类先列支持与不支持边界。
- 对照原件检查遗漏和顺序；重要数字/姓名/观点/笑点、忠实与适级改写分别审阅；词典词条、语境解释与生成例句来源分开。
- 检查分句、配音、字幕和句段锚点；局部改写后旧版仍可回放，新版不能定位到错句。未可靠对齐时允许普通播放，不冒称逐句同步。
- 题目检查答前载荷不泄露答案、选项音频不附带判定；问答允许预先审定的合理回应集合，歧义题可反馈/跳过。通过门槛按样本类别先定，不用总平均掩盖一种格式完全不可用。

### C．四端媒体与可恢复性

- Android、iPhone/iOS、Windows、macOS 各自验证文件/照片/音视频选择、上传、播放、点词、字号/窗口变化、录音、真人录像、导出和重新打开。
- 每端覆盖麦克风/相机拒绝与重新授权、来电/音频焦点、蓝牙切换、锁屏或后台、低存储、断网/重连、进程退出和同/新版跨端续学。设备没有前后镜头时不显示无效切换。
- 记录平台支持与限制，降级必须让用户可见且不静默改变用途；缓存播放不等于本地 ASR/专业评测。Mac 构建签名和真机不能由 Windows 截图或模拟器代替。
- 通过证据是每端可重复的主链路与关键失败恢复；平台核心链路不达标返回方案评审，不能擅删该端。

### D．预算、任务状态与幂等

- 先用离线替身模拟步骤成功/失败、响应丢失但实际完成、重复回调、租约失效、取消请求未确认、授权撤销、预算用尽及局部再生成。
- 核验接收、执行、结果、预留、实耗与结算各自状态。调用未知时先核查，不自动重新提交昂贵步骤或释放仍在占用的预留；已完成产物可先用，局部续做不全量重跑。
- 可确定不变量：未授权和超限时不执行新付费步骤；同一业务操作平台不重复结算；账本可追到执行尝试。供应商重试收费/退款由真实契约核验，不承诺失败免费。
- 替身测试通过后仍需获准的供应商最小调用验证实际回执、取消与计量；不得把替身计费当真实报价。

### E．多用户隔离、分享撤回与资产生命周期

- 两个合成账号覆盖草稿、原件、原始评测音频、个人词本、作品和发布快照；检查列表、直接资源访问和媒体授权，客户端隐藏入口不能替代后端核权。
- 指定人/链接/公开分期分别处理；撤回后新读取拒绝，缓存和短期媒体凭据的失效时效执行前定清。保留别人独立学习成绩的规则单列，不无差别删除。
- 来源撤权、取消任务、撤回分享、删除历史分别验收。导出/删除中断或部分失败需有范围和待处理回执，不把请求已提交当已全部完成。
- 外部发布按已获权限逐平台核验，已打开 App/已导出/未知不当作已公开；本站撤回不承诺收回外部副本。公共发现和直接代发未验证时保留分期，不阻塞私有学习。

## 5. 次序、门禁与停止条件

1. 先联评需求与共同契约，填完验证单；当前输出到此，不把计划登记为执行完成。
2. 获授权后先验证 A（核心纠音）与 C（四端关键媒体），并行检查 B；D/E 的确定不变量可先用合成场景验证，再接真实受控调用。验证实现范围单列，不等于业务全面开发。
3. 核心路线、权限、成本与质量门槛满足后才排获批范围的集成；预发布版本进行四端回归和人工走查，缺陷分级与复测证据齐备再验收。
4. 灰度须有具体候选版本、获邀人群、范围、预算、观察和回退方案，当前没有在线版本可灰度。初期本人→受邀朋友是候选次序，不是已批准邀请或发布。
5. 未授权外发、跨账号私有泄露、预算失控、重复生成/结算、核心数据丢失、无效录音伪评分等出现即停止相关路径/灰度，保存脱敏证据，按模块关闭新执行并核查未知任务；回退不得破坏已生成版本和账本。
6. 正式发布须人工验收、灰度问题闭环、分发/账号及回退演练通过，并由用户决策。发音效果不足回方案评审，不能以关闭核心纠音冒充完成；公共发现和未获批平台代发可以继续关闭。

测试执行窗口在路线、构建、设备与验证授权明确后估算，不按 Agent 数量或原型页数承诺日历上线日期。7/14天回访和延迟复习可作后续观察方案；少量自愿试用不构成统计显著的留存或学习效果证明。

## 6. 用户后续最少需要确认的输入

- 哪些 Android/iPhone/Windows/Mac 真机、耳机和 Mac 构建资源可用于验证，以及拟用的测试分发账号；没有的列为资源缺口，不重问已确定的人力方式。
- 技术联评后按验证单批准具体服务、样本/外发范围、保存规则和费用上限；当前无需先充值或购买账号。
- 若需要专业英语或发音质量结论，确定审阅或许可基准来源及验收口径；用户仍负责产品最终决策和人工验收，AI 团队不冒充真人专家。

测试负责人把这些输入并入联评问题清单，避免各端重复向用户索要同一信息。
