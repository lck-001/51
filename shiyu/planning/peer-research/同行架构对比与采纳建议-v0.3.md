# 拾语：同行架构对比与采纳建议 v0.3

核对日期：2026-11-11。用户要求找最新同行架构，比较优势与可借鉴内容。本轮Codex两个独立研究角色分别核查开源源码和商业语音产品，主Agent补查Duolingo并整合；未重新调用WorkBuddy/百度搭子，未安装/试用/采购或发送用户材料。此前三方技术评审仍保留，本文是新增同行证据研究。

## 1. 核查方法与新旧边界

优先官方工程文章、固定提交源码、维护者公告和具名供应商案例；产品更新只证明其公开描述的局部能力，不能还原整个生产后台。招聘信息和第三方技术栈目录不作为定版依据。

“最新”指本轮能核实到的公开资料，并非保证每家公司已公开其最新全部架构。Speak有2026-10-20工程文章、Loora有2026-11-05更新；Enjoy要区分2026新版方向与2025旧桌面源码。供应商案例的效果/成本数字不当作独立实测，更不承诺拾语同等收益。

## 3. 对现有方案真正有影响的发现

### 必须补强：实时对话与异步材料处理是两条执行路径

当前v0.2已有材料/媒体/评测Worker，但还应明确交互语音会话Module：连续对话不能让每个音频片段都排普通生成队列后才回应。材料提取、配音、字幕作品、专业声学评测仍保留受控异步路径。已有“自己说一句”可以先采用短录音提交，不代表首版必须建常驻实时房间。

### 建议采纳的轻量设计

1. **听、教学判断、说话、持久写入分责**：模型生成回应/建议，确定性代码执行词本、记忆、预算、分享等动作；模型不能通过提示词获得最终授权。
2. **先让初学者控制话轮**：“说完了”提交作为正式可用模式；自动轮次检测、打断和免手对话另做验证，避免停顿思考被误判结束。
3. **学习事实与规划分开**：保存可追溯的尝试、提示和专业评测；复习计划从这些事实生成。无需每轮同时调用三个昂贵模型。
4. **记忆按需且可管理**：只取当前材料、目标和相关困难点；个人事实/长期偏好另需明确保存、修正和删除规则，不自动长期保存全部对话或工作内容。
5. **测真实交流时延**：从学习者结束说话到听见回复，记录转写、判断、首输出、首音频与播放；观察尾延迟、误打断和不确定转写下的误纠正，不拿某供应商转写p50代替整体SLA。
6. **成熟基础能力优先复用**：媒体传输、队列投递、统一模型Adapter、共享契约有现成实现可评估；原始声学、权限、计费和灾后对账仍由平台契约保证。

专业发音继续是单独的声学评测能力。聊天自然、识别出了正确单词、语法判断合理，都不能证明专业发音准确率已校准。

## 4. 什么值得验证，什么不照搬

| 处理 | 内容 | 理由 |
| --- | --- | --- |
| 写入方案 | 交互/异步分路径、分责、提示与事实分离、端到端观测、端侧草稿 | 与现有范围吻合，不要求立即增加基础设施 |
| 有限验证候选 | LiveKit/WebRTC、流式ASR/TTS、端侧存储/缓存、成熟PG投递库、短对话记忆检索 | 先核对四端SDK、地域/隐私、断线/打断、授权/费用与可维护性，不自动接入 |
| 后续规模证据再评 | 自托管GPU推理、多地域会话部署、自训轮次模型、Temporal复杂工作流 | 要有负载、成本、数据、恢复及运维资源证据 |
| 当前不新增 | 写实AI头像、模仿同行课程商城/内容订阅 | 与用户自选材料、沟通和真人录制主线无必要关联 |
| 不直接复制代码 | 许可范围未澄清的Enjoy/english.now实现 | 公开仓库不等于自动获准复制/再分发；见开源证据报告 |

Flutter＋Python/FastAPI＋PG不因本轮研究直接推翻。更有价值的是补交互语音与教学职责，而不是换成某同行的所有框架。现有四端媒体、专业纠音、全局准入、恢复对账和运维门禁全部保留。

## 5. 范围和证据限制

- Speak三月平台与十月AI Tutor Call是不同范围/时间，不宣称后一篇替代全部前者。
- Praktika官方更新、OpenAI与Baseten案例不是同一时间/请求路径证明；模型分工叙述存在版本差异，不锁其模型型号，不采自报留存/收入作为拾语效果。
- Loora端上的是头像视频环节，不是“全AI离线”；截至该更新也不等于四端同等支持。
- Enjoy当前Web架构不能从旧Electron源码外推；english.now明确WIP。源码依赖声明不证明线上实际调用。
- Duolingo所引是内部工程Agent平台，不是其学习App或Video Call完整生产部署，精确发布日期未核实不填猜测日期。

本轮未找到可直接照搬、公开完整且已验证满足拾语全部四端/自有材料/专业纠音/Agent/分享要求的模板。这是本次证据范围结论，不是宣称市场不存在类似产品。
