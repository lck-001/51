# 商业语音同行架构证据：Speak、Praktika

核对日期：2026-11-11。目的：比较与拾语相近的英语沟通产品的公开架构，而非从界面、营销功能或招聘要求猜技术栈。本轮只读取公开资料，未试用、安装、调用付费服务或外发用户材料。

证据分层：A＝企业自有工程文章；B＝具名供应商案例（有商业宣传属性，不是独立审计）；C＝官方产品更新；D＝招聘/第三方，只作线索。本报告主结论仅使用A/B/C。披露局部能力不代表公开完整生产全栈，历史披露不自动等于当前所有流量路径。

## 1. Speak：本轮最强的直接工程参考

### S1：Building Speak’s Voice Agent Platform

- 官方文章，作者为Speak Staff Software Engineer；发布日期 **2026-03-24**，本轮读取正文。
- URL：https://www.speak.com/blog/building-speaks-voice-agent-platform
- 等级A，披露其语音平台，不是数据库/整个App完整架构。
- 可证实摘要：移动端经LiveKit Cloud/WebRTC传音频，服务端用LiveKit Agents连接外部模型及自有学习后端。平台同时采用ASR→LLM→TTS与speech-to-speech，按功能选择；披露多地域Kubernetes及就近供应商端点。对初学者停顿采用手动结束或语义轮次检测，并按阶段、语言、地区与供应商观察时延及尾部表现。
- 未公开/不能推出：iOS/Android的UI框架、数据库类型、队列、账本、四端客户端实现；文章中的部署规模不是拾语最低要求。

### S2：The architecture behind AI Tutor Call

- 官方文章，作者为Speak Software Engineer；发布日期 **2026-10-20**，距本轮约三周，是较新的具体功能架构披露。
- URL：https://www.speak.com/blog/the-architecture-behind-ai-tutor-call
- 等级A，专指AI Tutor Call；不能称三月整个平台已经被它全部替代。
- 可证实摘要：该功能从单一实时语音模型加提示词，演进为听取/判断/说话分责；语音模型不直接持有工具，保存纠错、记忆和结束通话由代码执行。判断结果有置信度等门禁，各行为可单独评估和灰度。文章还披露针对学习者停顿训练轮次检测，并记录判断、动作和提示版本以定位问题。
- 未采纳的推断：文中自报误判/打断改善不能当作拾语预期收益；其语音反馈不证明任一speech-to-speech模型都能提供经过校准的专业发音准确率。

### 对拾语的采用建议（工程判断，不是Speak原文）

| 建议 | 具体落点 | 首轮取舍 |
| --- | --- | --- |
| 对话、判定、持久写入分责 | Tutor回应不直接改词本、记忆、预算或分享；受控后端验证动作和版本 | 可直接写进Module/Interface，保持现有准入原则 |
| 人为结束话轮是正式交互 | 初学者点“说完了”才提交，可容忍思考停顿；自动轮次检测另验证 | 先手动、后免手，避免默认静音阈值频繁打断 |
| 双语音路线可替换 | 材料听读/录音评测走异步；需要实时聊天时另接低延迟语音会话 | 不是让全部学习过程都变成常驻实时房间 |
| 端到端与分阶段时延共同观测 | 从用户结束说话到听见回复，同时看转写、生成首token、首音频、播放卡顿 | 将交互指标补进测试计划，不能只看HTTP接口耗时 |
| 判断器先影子评估 | 新纠错规则先在获授权样本上旁路对照，未达标不改变用户回复 | 原声/提示/模型版本留证；不默认把私人录音用于训练 |

不照搬：多地域Kubernetes、自己的轮次检测模型训练、大量生产对话语料、每功能多个高价模型。适合拾语的先是分责和观测方法，不是Speak的全部基础设施。

- Baseten具名客户案例；本轮页面正文**没有显示发布日期**，因此只记2026-11-11核对，不从第三方转述反推精确发表时间，也不称其为最新全量架构。

- 限制：这是特定转写负载的供应商案例数字，不是完整问答端到端时延、P95/P99或拾语SLA；“近乎无限算力”是营销措辞，不采纳。OpenAI案例和本案例不能证明同一请求同时走两者，也可能是不同功能、时间或流量路径。

### 对拾语的采用建议（工程判断）

| 建议 | 可以借鉴 | 不宜立即照搬 |
| --- | --- | --- |
| 对话/测量/规划分离 | 当前会话专注沟通；已确认学习事实进入进步数据；复习与下一计划独立产出 | 不要求每一话轮都同时跑三个大模型；先用规则/结构化数据，必要时调用专职模型 |
| 相关记忆按需检索 | 依据当前材料、目标和最近困难点提供少量上下文；保留来源、版本与删除/撤权 | 不把全部聊天长期塞入prompt，不把模型总结等同客观能力事实 |
| 转写和前处理分资源 | 保留现有独立Worker与Adapter，按CPU/模型推理各自限制并发、观察吞吐 | 不因案例选择自建GPU或立即购买Baseten；先验证服务地域、非母语准确性、费用与隐私 |
| 供应商可替换 | 稳定输入输出和操作ID，按任务比较质量、尾延迟与完整成本 | 不将OpenAI兼容HTTP接口当作语义、计费、取消和评分完全兼容 |

## 4. 对现方案的直接影响

1. **不需要据同行改掉Flutter、FastAPI或PostgreSQL**：本轮商业同行公开资料没有证明它们的完整前端/数据库栈，更不能用未披露部分否定我们的候选栈。
2. **建议补一个独立“交互语音会话”Module候选**：未来免手自由对话可评LiveKit/WebRTC类传输；现有材料解析、TTS制品、复习调度和专业评测仍走各自受控流程。短录音问答可先验证更简单路径，不把实时房间当所有功能必需。
3. **对话智能不掌握最终副作用**：模型产出回应/建议；词本、记忆、费用、发布和来源读取由确定性代码与权限准入执行。多Agent是职责拆分，不是越多越好。
4. **专业发音继续保留原始声学证据**：ASR正确拼出词不证明读准；实时对话自然也不证明评分校准。不能拿同行语音产品文案替代我们专业评测验证。
5. **首轮更值得投入轮次控制和观测**：给初学者思考时间、可请求重复/慢放、别过度纠错，测真实端到端和尾延迟；具体指标待样本/设备/服务计划确认，不引用同行数字作承诺。

本轮没有供应商采购建议或价格比较。所有新增路线均为待评审候选，不能以竞品案例自动授权付费调用、跨地域传输用户音频或训练模型。
