# M04 手动验证用例

状态：全部待执行；没有 runner 与工具链时不勾选通过。

每项记录平台/系统、设备型号、构建版本、操作、预期、实际、文件路径（可脱敏）、截图或日志与结论。Windows 和 Android 分别填结果，不互相代替。

| 编号 | 操作 | 验收观察 |
| --- | --- | --- |
| M01 | 首次启动，停留十秒 | 不弹捕获权限，不亮摄像头/麦克风，不自动录制 |
| M02 | 选择文档/中文空格路径文件，随后取消一次选择 | 文件确已复制到受管目录；取消正常；文档不假装已解析 |
| M03 | 导入音频与带声音的视频，逐一播放 | 声音、画面、时长正常；拖动前中后位置可定位；暂停有效 |
| M04 | 导入不支持或损坏的媒体，尝试播放 | 有实际错误反馈，不显示学习或解码成功；界面仍可继续操作 |
| M05 | 点击录音，拒绝权限 | 提示拒绝；其他功能可用；不会自行重复请求 |
| M06 | 明确授权后录十秒，停止，回放 | 非空文件、实际声音、时长合理；结束后无麦克风占用 |
| M07 | 点相机预览，拒绝/撤回相机或麦克风权限 | 提示错误并释放资源；可关闭、重新明确点击；不会假成功 |
| M08 | 允许预览，开始录像，十秒后停止，回放 | 真画面与真声音、时长合理；检查实际容器及编码；无暂停续录按钮 |
| M09 | 录音时尝试录像/文件选择/播放并快速重复点击 | UI 互斥；不并发占用设备、不生成重复 take；停止仍可操作 |
| M10 | 播放后录音，相机预览后录音，录像保存后播放 | 播放暂停、相机释放，麦克风不会被两个捕获流程抢占 |
| M11 | 录制/预览时切后台、锁屏、恢复前台 | 尝试停止并释放；返回不自动开设备；检查文件完整与状态 |
| M12 | 录音时蓝牙断开、音频焦点改变/来电 | 如实记录系统行为；没有自动偷开麦；核查文件是否落盘/是否出现在列表；本稿不宣称完整恢复 |
| M13 | 相机被其他程序占用，无摄像头，Windows 隐私开关关闭 | 明确错误，可继续导入；修复后可手动重试 |
| M14 | 写入失败/空间不足（使用受控环境，不填满用户磁盘） | 不记为有效文件；错误后可操作；记录残留文件与清理需求 |
| M15 | 操作过程中关闭窗口，重复打开 | 无未处理崩溃；停止和释放尽力完成；不承诺进程被强杀时恢复 |
| M16 | 重启实验 | 本稿会话列表为空符合已声明限制；已有磁盘文件保留，不自动删除 |

通过门槛：M01–M10 必须双端实测；中断和失败项应给真实结果及问题单。任何未执行项写“待验证”，不能用静态阅读、浏览器演示或 mocked 测试替代原生媒体证据。
