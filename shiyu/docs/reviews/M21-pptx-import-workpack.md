# M21：PPTX 正文导入同入口工作包

排期调整：本项已排队，优先完成 M19-B“外部助手→学习候选→本人确认→App 学习”的核心链验证后实施。PPTX 与后续 PDF 均为保留的已批准需求，此调整不取消或降为永久不支持。

2026-11-18，产品推进单。承接已批准的 PPT 优先级、私有材料、手机/电脑任意设备上传与 M20 有界离线导入。M20-A 正在原生回归收尾，本文件不替代其实际验收记录，也不修改已验候选、源码、依赖或锁文件。

## 1. 下一项只补同一条链上的 PPTX

最小切片：**常规 PPTX 幻灯片正文中的普通文字与简单表格**，接入现有“导入文件”入口和 `MaterialImportSession`，完成选择→提取预览/警告→校对→source＋sidecar→私有草稿保存/回读→确认固定版→列表/冷启动恢复。

不增加上传中心、localhost 服务、PPT 编辑器、复杂提取选项、账号要求或自动生成任务。导入的是原文，不自动翻译、配音、分享或标记学习就绪。旧二进制 PPT、宏 PPTM、PPSX 等未纳入首批时清楚失败/提示另存 PPTX，不能仅换扩展名就接受。

沿现有精确 `archive:4.6.0`、`xml:7.1.0` 与 `crypto:3.0.8` 的有界读取/XML验证，不升级依赖。架构师核对后扩 `MaterialImportFormat` 与 extractor 分派、允许文件类型、预览文案和 sidecar 枚举；不要为新格式复制另一套 picker、Store 或错误协议。

## 2. 正文顺序是功能正确性的第一门槛

1. 由包根关系定位实际 presentation main part，并校验 PPTX 主内容类型；不硬猜固定路径或见 `ppt/slides/` 就算 PPTX。
2. 读取 presentation 的 `sldIdLst` 顺序，通过各条**正确关系命名空间**中的 `r:id`，查 presentation 对应关系文件的精确 slide 类型，解析到真实 slide part。
3. 按该顺序提取并保留明确页分隔和页序。**禁止按 ZIP entry 顺序、文件名字符串、slide 文件数字、关系文件排列或内部 sldId 数值排序。** 自造 `slide10/slide2/slide1`、打乱 ZIP/关系顺序的 fixture 必须验证。
4. 缺关系、重复冲突 ID、错类型、缺目标、非法目标、目标内容类型不符或损坏必需页必须失败，不能悄悄跳页后显示导入成功。未被 presentation 引用的孤立 slide 不拼入正文，但包内容仍受安全校验和累计预算约束。

首批按 presentation 引用列表保留全部页，包括存在隐藏标记的页；隐藏页显示可理解的页标识/提示，不静默丢掉用户原文。若提取结构暂无法区分该标记，按架构评审明确兼容边界，不假装已筛选。页码是原 presentation 的引用顺序，不是渲染后的打印页号。

## 3. 提取边界与讲者备注决定

### 首批提取

- 普通 shape 的文本正文：保留段落顺序、显式换行/制表符与中英文/emoji，连续 run 合并不额外造空格；字段等未支持结构不能无提示替换成空内容。
- 常规 DrawingML 表格：按行/列形成可校对文本，行分隔/单元格分隔与 M20 文本规则一致；合并单元格或复杂嵌套无法忠实处理时发警告，不复制/错序冒充精确表格。
- 同页对象先按文件内形状树顺序处理，不能宣称等于视觉阅读顺序；预览提示“文字顺序可能与页面布局不同，请校对”。不在本包加入渲染、动画播放或视觉排序引擎。
- 使用明确的页分隔和 blocks 来源映射；空页可以保留页序标识，但整包没有实际可提取文字时应返回无可提取内容，不能靠“第1页”标签造出成功正文。

### 讲者备注：首批明示遗漏，不增加开关

**首批不合并 notes 文本。** 原因是正文与讲者备注用途不同，备注还可能带模板页码、时间字段或隐藏讲稿，直接混合会造成重复/顺序混乱，并使来源不清；先保证用户所见幻灯片正文与页映射可校对。用户不需要理解新的配置面板。

检测到讲者备注关系/part 时，预览与 sidecar 明确记录：“讲者备注尚未提取，请核对原文件。” 这不是说备注不重要，也不是永远不支持；以后按已批准原文学习需求扩展时单独保留备注来源和页关联，不能悄悄与正文拼接。首批不因解析到了 notes XML 就自动把它当正文；所有 notes XML 仍走安全校验/预算，不以“忽略内容”为由绕过检查。

### 其他遗漏必须可见

| 内容 | 首批处理与用户表达 |
| --- | --- |
| 图片、截图内文字 | 不 OCR、不外发；检测到时提示“图片中的文字尚未提取” |
| 图表、SmartArt、嵌入对象、公式 | 未完整支持时不猜数据/标题，不递归运行嵌入文件；提示“图表或复杂对象中的部分内容尚未提取” |
| 母版/版式中的文字 | 首批不递归合并继承文字，避免页码/页脚重复；提示“母版或版式中的文字尚未提取”，不得称全篇完整 |
| 组合/特殊文本形状、修订/批注 | 精确支持范围由实现/QA记录；未支持而可能含文字时提示遗漏，不靠遍历所有 `a:t` 冒充正文 |
| 格式、位置、动画 | 仅提取文本，布局/动画不保留；无需给用户解释 XML、关系回执或资源状态 |

警告去重但不得藏在只有工程日志能看到的位置。预览要看得见，保存后来源 sidecar 保留；没有检测能力时不能把“无警告”解释为内容无遗漏。能校对的部分提取可以成功并带警告，损坏/不可信/超限必需内容则整体失败。

## 4. source、sidecar 与保存沿 M20，不再造新持久层

- 复用 `ExtractedMaterial` 的 exact text/source SHA、parserVersion、blocks 与稳定 warning。PPTX 新版 parser 名称/Schema兼容变化明确记录，不伪装旧 DOCX 解析器产物。
- source 保留原 PPTX 私有字节；sidecar 记录格式、来源哈希、提取文本哈希、页/块顺序与 part、warnings 和解析器版本。若现有 v1 blocks 只有 ordinal/part，可由 part＋页级块表达；需要新增 slideOrdinal 时小范围 Schema评审并兼容旧 sidecar，不直接改旧文件。
- blocks 的 UTF-16 offset 指向**精确提取文本**，中文/emoji/页分隔一并验证。用户校对修改后的草稿可不同，不能把提取 offsets 当作编辑后仍准确的位置。
- `prepareArtifacts()` 继续核查暂存源哈希，返回 source＋sidecar；保存经真实 Store，`finish(savedMaterialId)` 回读 same-owner 草稿并核两引用后才退休会话。确认仍由用户沿原流程完成，旧草稿/固定版本不覆盖。
- unknown、损坏、缺正文、加密、超限、取消/晚到/换材料等均不得改已有材料；不能为了完成 PPTX 自动补保存一份半篇草稿。失败只清理本会话暂存，不能删除已注册有效引用。

## 5. 架构师需先核的安全与容量项

### XML 与 URI 必须按精确语义处理

- 支持范围内的 Transitional/Strict PresentationML、DrawingML、关系 namespace/type 使用**精确 URI**，接受任意合法 prefix，不用 contains/后缀匹配允许伪 namespace。
- `r:id` 必须来自关系属性 namespace，不取任意同 localName 的属性；重复/冲突属性、关系 ID 和必需结构明确拒绝。
- slide 的内部 Target 按来源 part 所在目录与 OPC 包规则解析。合法的相对路径需正确规范化；禁止逃出包根、scheme/authority、外部 TargetMode 或歧义编码、片段/查询混淆。不要简单拼接路径，也不要不分语义地拒绝所有 `..` 而破坏合法包内引用。
- Target 指向 slide 必须为内部包 part。其他外部链接仅保留普通显示文字并发“不读取外部链接”的既有警告，不访问文件系统/网络。无宏/嵌入执行。
- 沿现有 SafeZip/SafeXml 入口验证所有 part；notes/master/layout/theme 即使不提取也不能绕过 DTD/实体、字符/深度/event/attribute/CRC/真实解压输出等检查。

### 预算必须跨页累计

沿 M20 的 source、entry、累计实际 inflated、XML、text code points、entries、depth、events、attributes 与 app killable worker/deadline。**每页/每关系文件新建一套预算再相加**不能算总量受限；一份 PPTX 的页面、notes、布局和被忽略 part 共用整包限制与真实输出计数。

先保留 M20 已审单次候选限额，不因 PPTX常带图片就静默放大。普通教学/工作 PPTX baseline 要有记录；超限清楚提示“这份材料较大，请按页拆分后再导入”，不修改原文件、不静默截断、不宣称永久不支持长材料。整个提取文字不能靠页标签/重复块浪费预算或绕过真实正文检查。

## 6. 本批顺带收口的两个 M20 非阻断项

在 PPTX 源码改动同一受审批次内收口，不原地改写已验 M20-A 候选：

1. **显式 library 校验硬化**：核对当前 `archive:4.6.0` 实际使用的 ZipDirectory/ZipFile API，将 verify/throwOnError 需要的严格行为显式设置/留证；不得用库开关代替 SafeZip 已有本地/中央一致性、CRC、真实输出/累计限额检查。坏 CRC、截断等原独立用例不能放宽。
2. **DOCX footnote/endnote 中文警告准确化**：当前 `annotationsOmitted` 同时覆盖 comments/footnotes/endnotes，界面不能只说“批注未提取”让用户误以为脚注/尾注已保留。最小修复为准确的中文“批注、脚注和尾注尚未提取”（或经映射拆分后按实际显示），保留稳定来源/旧 sidecar 兼容；不能反过来宣称首批已提取脚注/尾注。

原 M20 parser 独立19项＋实现11项须同批实际回归，再加 PPTX 新例；原生应用、Shell和保存生命周期受改动影响的测试也要运行。历史 M20-A结果保持历史原样，本批单列新结果/候选，不在旧记录中追认未执行功能。

| --- | --- |

| 遗漏提示 | notes、图片、chart/SmartArt、master/layout、未支持对象各有原创fixture；预览可见中文提示，sidecar保留，同一遗漏不重复刷屏；不把图片或notes文字混成正文 |

## 8. 后续与当前用户动作

PPTX 同入口验收后继续 PDF 成熟 Adapter 调研/评审，保留“文本层可提取、无法提取可能需OCR、加密、损坏/特性不支持”分别处理；不取消PDF目标、不手写正则抽取、不因账号尚未开通就停止离线工作，也不偷偷把文档发云OCR。

当前无需用户决定库、URI规则、预算或是否提取备注，以上由PM/架构师/QA收口。本人系统选择器/真实私有材料验证到达时再给具体步骤；本批不操作主机桌面、不读用户文件、不播放声音、不发云请求。
