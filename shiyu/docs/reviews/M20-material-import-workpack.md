# M20：离线文档导入与真实材料页纵切

2026-11-18，产品工作包。用户已选择暂不开通账号，先做无需账号能力；承接已批准的文档/PPT/Word/PDF、手机和电脑均可上传、默认私有、长内容可切分学习，不新开需求或扩手工学习内容编辑器。本文件未开发、升级依赖、打开文件选择器、读取用户材料或请求网络。

## 1. 下一最小可交付切片

**M20-A 选择 TXT＋DOCX，必须接到现有 App 的添加/材料流程，不能只交一个能解压的包。**

实际路径：添加材料→导入文件→系统选择一份文档→本机提取并提示遗漏/限制→在现有标题/原文编辑区预览校对→保存私有草稿并回读→用户确认固定版本→材料列表可见→重启仍在。导入只生成原文草稿，不调用 M19 生成任务、不翻译、配音、计费、分享或标学习就绪。

TXT 提供最小编码/取消/落盘验证，DOCX 承接最高优先级的真实文档价值；仅完成 TXT 不算本切片全部完成。Word 首轮指 DOCX；旧二进制 DOC、加宏 DOCM 暂不标支持，保留后续兼容目标并清楚建议转换，不启动本机 Office/LibreOffice/宏。

紧接 M20-B 做 PPTX 同一流程与原有纯文本提取 Interface，不新增上传中心。M20-C 对 PDF 采用另行审过的成熟提取 Adapter 和质量矩阵，不在 DOCX/PPTX ZIP/XML 实现里拼一个 PDF 正则解析器。PDF 仍是已批准优先来源，不因技术分批被取消或降成永久不支持。

## 2. 已核对的依赖和入口

- `validation/playback-01/pubspec.yaml` 已直接固定 `file_selector: 1.1.0`、`path_provider: 2.1.6`。其 `pubspec.lock` 已有传递依赖 `archive: 4.6.0`；本机缓存也有这个精确版本。
- 本机缓存有 `xml: 7.1.0`、`xml: 6.6.1` 和 `petitparser: 7.1.0`；当前应用锁中已有 collection/meta 等相关依赖，但 **xml 不在当前应用锁中**。缓存存在不等于已准入、已能离线解析或无锁变更。
- 现有 `AudioMaterialStore.select()` 演示了 file_selector，但它的内存路径 Map 与实验 owner/revision 不是材料持久导入方案；本包不得复用该 Map 当材料库。
- `client_shell` 添加页目前“上传文件 · 尚未接入”只是占位，没有真实导入回调。本包必须替换成真实可用的“导入文件”动作，经 App owner 注入，不把插件/路径塞入 Shell。

**架构建议：优先纯 Dart 的 OOXML ZIP＋XML 文本提取，避免为本机文件另起 HTTP 后台。** 导入是本地文件/字节 Adapter＋有界解析＋已有 MaterialStore 落盘，未见需要 localhost 服务的事实。具体包/版本由架构师做小范围离线依赖求解、安全能力与锁差异评审；新增直接依赖不等于升级所有包。现在不运行 pub、不改任何 lock，也不手写完整 ZIP/XML 标准库来省依赖。

### Android 必须先解决的读入门槛

当前已缓存 `file_selector_android` 的 `_xFileFromFileResponse` 使用 `XFile.fromData(file.bytes, ...)`。这证明不能只依赖 Dart 层 `selected.length()` 后的限制来宣称安全：文件可能在 Dart 校验前已由原生整份读入内存。源实现只支持提出风险，不是已跑过大文件/OOM 的证据。

架构师在实施前必须核对该精确插件的原生读取路径，决定如何在分配前限制/有界拷贝：能复用原插件安全路径则复用；否则评审窄的 SAF→应用私有临时文件 Adapter 或范围明确的补丁，并保留许可证/上游版本/改动和回归。不能用“只允许20MB”文案掩盖原生先读1GB的问题，也不能因此引入本机HTTP服务或全盘读权限。Windows 的 XFile 私有路径处理与 Android content URI 分别验，不能互相推定。

## 3. 小 Interface 与现有页面衔接

建议把变化留在三个真实位置，名称可由架构师收口，不增加通用插件平台：

1. **App 拥有的选择/读入 Adapter**：系统单文件选择、取消、授权读取、有界私有临时副本、显示名称和格式探测。可供后台测试注入合成输入；只有用户点击时才调用原生 picker，初始化/恢复不打开对话框。
2. **无 UI 的提取 Module**：`extract(source, limits, cancellation)` 返回提取文本、块/页位置（格式支持时）、格式/解析器版本、警告、源哈希和不含路径的临时来源引用，或稳定错误。它不直接创建学习版/调用供应商，也不提供任意URL/文件路径执行能力。
3. **Shell 小回调**：例如 `onImportMaterial()` 返回取消/可校对内容/失败；具体签名以当前保存流程为准。回填已有编辑区，用户保存仍走真实 `MaterialStore.createDraft/updateDraft`，确认仍走 `confirmVersion`，不要新做第二套材料列表或重复存储。

选择结果只带应用内可信临时引用；原始 OS 路径/content URI 不进入 Widget、通用 DTO、日志、系统媒体信息或公开 Git。若需保存源文档，走私有 `ArtifactRef`；提取/保存来源信息同样保存在私有材料相关制品或经评审的小扩展中，不把绝对路径当永久引用。

默认保留源文件的应用私有副本和原文提取来源，便于校对；不得修改/移动用户原文件。保存前的临时副本属于导入会话，取消按明确策略清理；已经保存的草稿/附件不因退出编辑器被删除。当前 Store 的制品写入与建草稿不是一个跨文件事务，不宣称绝无孤儿制品；需识别临时/已引用状态，失败不给“保存成功”，后续清理不能删有效引用。

### 不覆盖正在编辑的内容

- 已有未保存文字时，先确认是否放弃当前未保存内容，再发起新导入；安全默认“继续编辑”。取消 picker/提取失败时不能抹掉原编辑内容。
- 导入/解析期间禁重入。取消、返回或选了另一材料后，以导入会话 epoch 丢弃旧结果，不能让旧文档晚到内容覆盖新编辑器。
- 回填后算未保存修改；返回继续沿 M18 保护。保存不能重复生成多份草稿；与既有保存/确认忙碌状态相容。
- 用户看到“正在读取文件”“正在提取文字”“已提取，请校对”；百分比没有可靠分母就不显示假数。格式/质量问题用简明中文，不显示 ZIP/XML/URI/调用回执等实现术语。

## 4. 各格式真实支持边界

| 格式 | 首轮提取要求 | 不得夸大的部分 |
| --- | --- | --- |
| TXT | UTF-8（含 BOM）和明确定义的 UTF-16 BOM；规范换行，保留段落/中文/emoji；空文件与无效编码清楚失败 | 不默默用 replacement character 吞字符；GBK/未知编码尚未支持时提示转换，不声称已正确提取 |
| DOCX | 验真实 OOXML 容器/内容类型，只取已允许正文 part；按文档顺序保留段落、tab/换行，表格按行/格可读展开；命名空间按 URI 处理 | 图片/扫描图、公式、图表、文本框、修订/批注、页眉页脚/脚注等未实现部分必须列警告；不以“提取到了部分字”冒充全文/原版式 |
| PPTX（M20-B） | 按 presentation 与关系映射的真实幻灯片顺序，提取每页文本与明确页分隔；表格/文本框覆盖范围实证 | 不按文件名字符串排 slide1/10/2；对象顺序不保证视觉阅读顺序，需提示校对；备注/隐藏页/图表/图片等是否包含逐项明确，不能默默称全部 |
| PDF（M20-C） | 独立 Adapter 评审后才支持文本层提取；用多栏、字体映射、中英混排、页顺序等样本检质量，保留页映射与警告 | 当前 ZIP/XML 能力不能提取 PDF；空文字可能是扫描、字体映射或解析失败，不能直接断言“这是扫描件” |

PDF 的用户结果至少区分：可提取文字但需校对；无法提取可读文字、可能需要 OCR；加密/需要密码；损坏/该特性尚不支持。不能靠搜索 `/Encrypt` 或字符串截取就断定可靠分类。未具成熟解析 Adapter 前入口明确“暂未支持 PDF 提取”，不要接收后显示导入成功。OCR 是独立能力，未实现时不造文字、不偷偷发云；后续可单独评审本地 OCR，但本包不安装。

## 5. 长文目标与单次处理安全

“任意长内容可分开学习”继续成立为产品目标；本机一次导入必须有限资源，不承诺无限内存、无限解压或一次完整处理。限制描述为本次设备/处理批次，不写“本产品永久只支持短文”。

架构师需冻结并记录可配置限制：输入压缩字节、ZIP条目数、单 entry/累计真实解压字节、压缩比异常、XML字节/深度/节点数、提取字符/块数、处理时间、临时磁盘与并发数。阈值由当前 Android/Windows 实测决定，不能只靠猜值通过；普通教学/工作文档要有可用基线。

- 大文档读取可受控分块/分段计划；DOCX/PPTX 需先验证结构和有界解析，不从截断ZIP随便取前一半假装成功。
- 超出本次能力时提示“这份材料较大，请先按章节/页拆分后导入”，保留原文件，不保存无提示的截断草稿、不截一段后标全文成功。
- M20-A 不必先搭完整大文档分布式处理，但要输出可识别的“本次容量不足/建议拆分”，保留后续原文定位/切分设计。完整自动切分若尚未实现明确未完成，不用文案当能力。
- 后端当前 intake 有自己的 UTF-8 字节上限，本地导入不能因提取成功就承诺将来整个文本能一口气送入 M19；计划阶段按同版原文定位与段落切分，防止丢文或重复生成。

## 6. ZIP/XML 与文件处理安全门槛

- 格式以签名/实际容器及内容类型校验，扩展名/MIME 只用于选择提示。拒绝伪 DOCX/PPTX、重复/冲突 part、加密ZIP、损坏中央目录/CRC和不支持的压缩方式，不悄悄跳过异常必需 part。
- 不“解压到用户目录”，仅按白名单读取必要 part；拒绝绝对路径、`..`、链接/符号链接和冲突规范化路径。即使不写磁盘也要防路径混淆，不能因只取 XML 就忽略包结构。
- 解压限制检查必须覆盖**实际输出**，不能只信中央目录里自报大小/压缩比；若库在有界检查前分配全量内存，列阻断问题再选有界输出/读取路径。不得靠 timeout Future 伪称已经终止解压。
- 禁 DTD、自定义实体、外部实体和外部关系抓取；拒绝恶意实体/深嵌套，XML package 默认行为需实际核对。没有网络 Adapter 也不代表实体膨胀安全。
- 宏、嵌入对象、外部链接和附件不执行、不打开、不递归解析；正常链接文本可当纯文本，不能跟随下载。预览纯文本不渲染HTML/脚本。
- 解析工作避免阻塞 Flutter 主 isolate；取消/超时要实际终止或隔离 worker 并清理会话，不能让旧结果继续提交。存储/选择器权限和平台 channel 仍归 app，不在解析 isolate 里越权操作。
- 已保存文档默认仅本机本人可见，不自动公开或云备份。日志和公开测试只用自造材料，源文件名/正文/路径/截图与音视频不进入公开源码。

## 7. 独立验收矩阵与交付证据

| 验收层 | 必须实际验证 |
| --- | --- |
| 纯提取 | 自造 TXT/DOCX，中文/美式英文/emoji/换行/表格/命名空间变体，内容顺序与预期逐项比对；PPTX 后续验证真实页顺序，不以“非空”当成功 |
| 文件安全 | 伪扩展/空/坏编码/损坏ZIP/CRC/重复part/路径穿越/加密/宏/外链/DTD实体/深XML/ZIPbomb/越界真实输出，明确拒绝且无网络、无原文件修改、无超限内存结果 |
| 会话/取消 | picker取消、权限拒绝、丢文件、读中失败、解析取消/超时、重复点击、返回/换材料后晚到、已有未保存文字保留，不创建假草稿或覆盖当前编辑 |
| 真持久 | 真实临时文件经现有Store保存/确认，源制品引用/哈希与提取文本可回读；新进程/重启仍在，失败不报成功；不生成学习版、不发云 |
| Widget | 真实导入Callback→已有编辑器预览/校对→保存/确认→材料列表，dirty/back保护与原粘贴流程不退化；文件入口有明确支持格式/限制 |
| Windows 原生 | 后台注入合成文件/受控 picker seam可先验；真正桌面系统选择器交互待本人方便时参与，不能未授权弹窗/抢焦点；未操作就明确“原生选择器人验未做” |
| Android 原生 | task-owned无窗口模拟器的SAF合成文档导入、取消、权限/返回与重启链；原生字节读取上限在分配前实际成立；模拟器不是用户真机通过 |
| 范围/权限 | 最终 manifest无新增全盘读权限/不必要网络；iOS/macOS接口保留但无实机/构建证据时明确未验，不从插件支持列表推定四端完成 |

M20-A 完成需要一条真实 App 纵切和独立 QA，而非只交纯 Dart tests；依赖、设计/源码审查、分析、构建、合成数据运行、结果边界和功能分支交付分别留证。M20-B/C 同入口分批进入验收，不能用占位标签算支持 PPT/PDF。

## 8. 开发前的内部架构决策

后端/客户端架构师与 QA 先收口：① 精确 ZIP/XML 依赖及有界 API是否可用；② Android 原生读取上限/私有拷贝 seam；③ 提取来源制品与现有Store的最小映射；④ Shell回调/取消epoch与保存责任；⑤ 首轮限额和可复现安全fixture。上述为团队内部可解决事项，不让用户选库/框架/阈值。

评审后实施 M20-A；无账号不阻碍本项。只有真实用户文档/桌面选择器/声音或外部服务需要本人参与时才交具体范围与步骤；当前无需用户立即操作，不打开主机桌面文件选择器，也不催账号。
