# M13 产品规则：后台与锁屏媒体

2026-11-12，产品评审输入。沿用已审需求及GLOSSARY；本页只确定产品规则和验证边界，不修改代码、依赖、设备或权限，不创建自动化。

## 四种场景

| 场景 | 产品规则 | 不允许的推断 |
| --- | --- | --- |
| 已主动开始的音频 | 明确听音模式下，切后台/锁屏应有连续播放路径；未在播放则不因离屏启动。独立学习音频即使来源是视频，也按音频规则处理 | 当前实验全暂停不能算离屏听音已支持 |
| 用户手动暂停 | 保持暂停；返回前台、解锁、焦点恢复或重新授权均不擅自续播。用户可从界面或系统媒体控制明确播放 | 不以“进入resumed”覆盖用户意图 |
| 视频播放切后台 | 默认暂停画面及该视频播放。视频转为“仅听音”是显式模式与后续独立验收项，不默认暗中保留声音 | 该分期不削减已确认的材料音频生成/听读能力 |
| 录音、录像或相机预览切后台 | 停止采集、释放麦克风/相机，保留可用片段并显示保存结果；返回后需主动开启。后台连续采集不纳入此包 | 结束采集、权限被拒或在设置中重新允许，都不自动开麦/开相机，也不自动恢复之前播放 |

## 恢复语义

系统明确标为可恢复的**短时音频焦点中断**，仅在中断前确实播放、用户意图仍为播放、同一媒体/学习版本与同一播放代际、焦点恢复且输出路径可用、期间未进入采集或其他互斥任务时，才允许恢复。没有可靠“可恢复”信号时保持暂停，由用户继续；不自行猜一个静音/时长阈值。

期间发生用户暂停、切换材料/账号或新播放任务，应使旧恢复资格失效；迟到的旧事件不能重播旧内容。应用重启/强制终止后可恢复位置，但首次播放必须由用户发起。耳机拔出、永久焦点丢失或输出路由不明时保守暂停，不突然转外放。查词/例句试听和录制导致的交互暂停不归入可自动恢复的系统短中断；收起词卡仍不自动续播。

## 范围与门禁

- 连续听音、手动意图、音频焦点/锁屏/中断、前台采集及恢复属于已有需求，应补实现与逐端证据，不因实验简化静默删去。当前源码在paused/hidden/detached统一停录、关相机并暂停播放器，只是保守实验行为。
- M13当前仅产品/架构/QA评审，不声称后台能力已实现。M12 Android实机仍为`deferred_device／未验证`；已构建/签名核验不代替安装和实机。Windows前台基础闭环不代替后台/锁屏或新版回归。iOS/macOS后验但保留范围；专业声学评测仍未接入。
- Android系统媒体会话、前台媒体服务/可见提示和锁屏控制，与“用户反馈首版仅站内提醒”是不同能力；后者不能作为跳过平台要求或自动扩增通知权限的依据。具体系统条件由架构评审核对，实际权限由当前设备用户决定。

## 下一评审必须回答

架构/QA需给出播放用途、用户意图、暂停原因、采集状态与播放代际的独立模型；逐端生命周期/焦点/耳机/锁屏规则及所需系统能力；可自动恢复与必须手动恢复的事件表；旧事件、新材料、重启和拒权负例；静态/合成可核对项与必需实机证据。内部路线由团队提出，不让用户选框架参数；评审后才决定最小实现包，不以本页提前放行代码或设备操作。
