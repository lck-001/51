# 编辑动作的焦点可见性

反向 Tab 选中的保存或确认按钮可能仍在底栏下方；保存状态文字出现时，也可能把仍保留焦点的保存按钮推到视口外。真实文件存储与 Widget 测试分别复现了这两种情况。

两个编辑按钮现在使用内部可见性边界：沿标准焦点回调和父组件更新，捕获当前真实按钮节点，在布局完成后对最近的编辑滚动位置做一次必要的显露。已可见时不滚动；所属范围、输入、页面、路由、节点或滚动位置变化后，旧请求失效。按钮资格仍取原按钮的 enabled 状态。

内部边界不选择焦点，不恢复页面级焦点，不抢用户已移到其他控件的焦点。稳定的外层动作 key 保留了列表前置内容清理时原按钮的身份，内层按钮 key 和数据回调保持原样。

## 验证

- 两个视口下的六个可见性失败场景均通过；保存布局变化后的目标仍是同一个 Save 节点。
- 两个忙碌期间主动移到刷新按钮的控制场景保持原节点；动态导入预览清理后，Save 节点及已保存的来源引用保持。
- 14 项生命周期检查覆盖过期所属范围/输入/页面、路由与挂载变化、真实滚动位置替换、已可见时零滚动及同帧合并。
- 稳定动作 key 对应的 8 项可见性、14 项生命周期、9 项既有键盘组件与6项仓库键盘回归均通过独立核验。
- 采用后，仓库原有完整 client_shell **64/64**、playback **119/119**、格式检查及整包静态分析通过，源码及锁/config 校验一致。
- 新增两份仓库测试文件，8 项真实 Widget 回归全部通过，使用真实存储委托控制 IO 完成时机，未模拟焦点或矩形；覆盖反向显露、同节点保焦、不抢焦点、过期回调取消及导入清理后的节点身份。

## 后续验收

本轮是源码与 Widget 验证，新原生包的完整材料链仍需复验。保存后的自然焦点可能保留在 Save 或退到页面级 Scope；本修复只显露当前真实选中的动作，不承诺自动回到某个控件。混合输入的材料验收与自然连续键盘路径分开记录。
