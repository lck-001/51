# 文件导入与候选学习的无窗口组合回归

本包只新增测试，不修改产品实现。以 B1 的有限交付为基础，组合原有文件提取、私有桥接、界面校对确认和存储重开；不新增产品按钮、测试控制协议或存储权威。

## 验证范围

两条独立路径分别使用原创 TXT 和 DOCX。文件选择边界注入本测试新建的临时文件，其后的真实提取 worker、源文件与来源 sidecar、MaterialStore、LearningStore、RootLock、桥接 socket 及 Shell 回调均保留。调度包装仅转发真实 IO，界面侧直接 receiveCandidate 会主动报错，候选必须经真实桥接送入。

- TXT 使用 BOM 和 CRLF，区分原文件、提取文本与界面校对后固定原稿的三种摘要。用旧摘要投递必须拒绝，只有实际固定原稿的摘要可接收。
- DOCX 使用原创中文段落和表格。此两例不承担中英混排、emoji 或所有 Office 兼容性的覆盖；其他导入矩阵另有记录。
- 核对校对后的授权 source_read、原件不变、两份来源制品、重复投递唯一候选、界面修改英文后确认成 external 部分可读版；保留原始声明及既有学习内容。
- 由界面显式选择新内容，拼合实际逐词阅读组件中的整句文本核对。无音频，不创建或请求原生 Player。
- 按实际 bridge drain、关闭两 Store、释放 RootLock 的顺序退出，再正常打开 Store，检查确认映射、学习版、来源附件和旧内容。这里只称 Store 重开，不称 App 双进程冷启。

## 失败记录与独立验收

作者初期遇到测试支架问题：保存清理尚忙时过早点确认、导航 key 与实际不符、弹层动画未完成时命中点离屏，以及按整句查找逐词 Text 的错误假设。均通过等待真实按钮状态、有界动画完成、使用现有 key 和拼合实际逐词内容修正；没有修改产品或放宽业务断言。

作者定向两项通过，三文件静态检查无问题。独立 QA 另行实跑 TXT／DOCX 两项，2/2通过、退出0；整 probe `flutter analyze --no-pub` 无问题、退出0，并核对三个文件没有直接写入候选旁路，按上述范围有限验收通过。本轮真实传输为 AgentBridgeClient 的本机帧接口，不重复声明已重验 stdio 代理或外部模型。

未覆盖系统文件选择器、人手交互、原生客户端 MCP 注册、真实模型整理、音频质量、专业发音评测、四端实机及发布。原生导入和当前会话经 stdio 到实际候选箱的历史证据分别保留，不拼称同一次端到端全通过。
