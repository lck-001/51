# M19-B：外部助手送入学习候选的小纵切

2026-11-18，产品工作包。采用 `GLOSSARY.md` 的“学习候选”“来源声明”。承接用户“两种 Agent 都要，先验证外部助手接入”、暂不开通新账号的决定，不新做通用 Agent 平台、课程、手工音频编辑器或自动公开功能。本文件不开发、不调用现有账号/CLI/TTS、不升级依赖、不使用用户私有材料。

## 1. 优先交付的价值与边界

TXT/DOCX 已覆盖一条真实材料输入；接下来优先验证**外部助手整理好的内容→本人校对→App 内学习**，使产品走向英语学习而非仅增加材料格式。PPTX/PDF 保留已批准队列，待本条核心链验证后继续，不取消。

小纵切只针对一份已确认原文：外部工具实际送入原创双语句结构、来源声明和可选合法音频→接收为本人私有学习候选→本人预览校对并确认→新固定学习版→App 阅读或播放→重复确认与冷启动稳定。接收、确认、学习就绪和公开发布是不同事实，不能合并为一个“成功”。

此链不要求平台主动读全终端记录，也不自动代调用户已有模型账号。没有音频时可以是**部分可读**的学习版，但不称听力闭环；有合法真实朗读音频且制品/时锚验证通过，才可进入相应播放链。静音 fixture 永远只是结构测试，不是英语配音；专业发音评测仍未接通，不出现假分。

### 已审定的首个实施分片：M19-B1

M19-B1 为“受限外部文本学习候选”，先完成双语文本、持久候选、校对/确认幂等与 App 可读闭环。媒体字段出现即明确返回暂不支持，不忽略后显示成功；确认后的学习版为 `partial` 可读，不称可听或发音评测完成。

M19-B2 保留合法音频与时锚接入目标，先评审制品幂等注册/取消和校对后音频失配处理，再执行下文媒体条款。分片只调整实施次序，不取消听说目标，也不把传输身份当作模型/音色权利证明。

## 2. 一个输入包，不开放任意执行

对外输入需有 Schema 版本、外部 delivery ID、原文绑定/指纹、双语句结构、来源声明和可选媒体清单；确切字段由架构师收口。原文绑定必须由 App/服务实际读取固定材料版本核对 owner、material/version 与内容指纹；不能因为外部包自称匹配就承认。首批原文未匹配或不存在时拒绝进入确认流程，不自动猜映射、复制新原文或覆盖用户现有材料。

音频如有，需声明来源/使用权说明并提供实际私有制品、SHA/长度/格式、句时锚；链接不能成为任意下载授权。首批采用受限传输/预先获准的附件取入方式，不跟随任意 URL、私有网地址或本地路径。文本/媒体/总量分别限额，未知或超限明确拒绝，不截断后显示完整。

**身份/传输来源可核，不等于模型和版权声明已核。** 保存三类信息，显示也不得混淆：

- 经入口验证的提交方/integration、传输方式、接收时间和实际包指纹，来自可信上下文，不信请求体的 owner/scopes。
- 原样保留的来源声明：提供方自述整理方式、模型/版本、人工参与、音频来源/许可等。缺失、未知、未独立核实如实标记；不能显示“官方模型生成已认证”“音色权利已证明”。
- 系统确实完成的校验：原文绑定、容器/哈希/时锚与结构等。校验文本结构不证明地道美式表达，模型自评不作为语言质量唯一证据。

首批只收内容，不接收工具脚本、执行提示、宏或自动发布命令；外部文本中的指令当材料数据，不改变平台权限。

## 3. 学习候选必须先有真实持久层

沿现有 Store Interface 扩一条窄的学习候选路径，最少支持接收、本人列表/读取、保存校对修订、确认/拒绝；是否单列 CandidateStore 或纳入 LearningStore 由架构师根据事务/恢复职责决定，不新建第二套文件权威。

- 接收只落本人私有学习候选，状态为待校对；未确认时不出现在正式学习列表、不自动生成学习版、不公开，也不触发平台生成任务/费用。
- 原始输入包/来源声明不可变保留，校对内容单独有 revision，不能覆盖原始声明；本人修改英文时不能继续把旧音频/时锚当作已匹配，需要重新验证或降为部分可读。
- 同 `(可信owner, integration, delivery_id)` 同内容持久幂等，重启仍回同候选；同键换内容冲突。不同提交重新送来的更新可以建新候选，不覆盖已确认学习版。
- 本人读取/校对/确认与外部送入权限分离；receive-only 不能读回其他材料、确认、生成或公开。跨 owner 不泄漏候选是否存在。传输接收成功只说明候选持久送达。
- 拒绝候选不删除已确认材料或历史版本；重复拒绝/过时修订有确定行为。新候选晚到不切换当前学习/编辑上下文。

### 确认不得重复创建学习版

确认必须使用候选 ID＋expectedRevision。以**候选固定修订**作为持久确认幂等键，保存候选修订→学习版 ID 的不可变对应关系；重复点击、外部回放、重启/崩溃恢复都返回原对应版，不创建第二个版本。

当前 `LearningStore.createVersion` 没有候选确认幂等参数，不能简单“先查 map，再 createVersion，再写 map”。架构评审须先选择并证明 Store Interface 内的原子确认，或带持久意图/确定性目标ID及恢复查询的等效方案；必须覆盖**学习版已创建、确认回写尚未完成就崩溃**的窗口。跨文件/跨存储无法原子时明确恢复协议，不靠内存 Map、时间戳去重、直接改 manifest 或测试后手工修文件。

只有确认成功且实际 Store 回读一致才显示“已加入学习”；失败不能先显示成功，不能半确认后静默再建版。原文新版本与候选绑定不符时要求重新送入/校对，不把旧音频或进度百分比搬到新原文。

## 4. 来源 Schema 先审，再接学习版

当前学习来源只支持 `manual/synthetic`。外部助手输入不能强塞为 manual、provider 或平台已核生成；先评审可表达**外部提供＋来源声明＋可核校验范围**的 Schema 演进、旧版读取/恢复与 UI 显示，再经 Store Interface 写入。术语仍用学习候选/来源声明，不把传输提供方等同于模型调用供应商。

制品注册、学习版创建与候选确认都走 Store Interface；Python 接收端不能直接写 Dart manifest 或自造 FileStore 索引。跨端材料 ID/版本的映射与内容指纹必须有真实验证 Adapter；尚未桥接时列未完成，不把服务端接收 API 当 App 已收件。

确认后的结构状态继续由实际英文/媒体/时锚校验决定：无媒体为部分可读，坏媒体或绑定不符不进入可播状态。若有音频，保留实际合法来源与用户确认记录，不能从“外部工具身份已验证”推断版权已核。Open 默认暂停，既有同版进度/旧回调隔离规则不变。

## 5. 传输选择由架构师收口，证据分两层

优先复用已评审受限送入边界和本机/服务可用能力，以一个真实调用入口桥接 App 的学习候选 Store；不为演示引入公网服务、广泛文件权限或后台任意读取。若采用本机连接器/工具，需明确当前用户绑定、有限 scope、凭据的安全本机配置与撤销；不能把合成 TrustedCaller 当生产登录。不要为了绕账号问题自行启用第三方 CLI、复用聊天会话密钥或默认云调用。

| 证据层 | 可证明 | 不可宣称 |
| --- | --- | --- |
| 受控协议/Store 验证 | 自造发送端经真实入口→私有候选→确认→App 内容，真实持久、越权/失败/恢复可验 | Codex、WorkBuddy 或百度搭子已经接通；其账号免费/额度获准；平台能读取各端记录 |
| 真实外部工具验证 | 至少一个明确的外部助手实际调用受限工具，返回持久候选结果，App本人空间可见并按确认流程学习 | 所有助手已支持、模型/版权已认证、自动中文转英语/TTS/评分全链已经完成 |

真实外部工具暂不可用时，继续完成候选/确认幂等/来源Schema/入口失败路径等可独立工作，效果状态明确保留。不得把当前聊天中手写 JSON 或测试进程的 HTTP 请求改名为“Codex 实际工具接入”。

## 6. 小纵切验收场景

| 必验项 | 实际通过证据 |
| --- | --- |
| 私有候选生命周期 | 原创小样经真实传输落候选，新进程回读；未确认不成学习版、不公开；本人校对/拒绝有效，外部 receive-only 无权确认 |
| 绑定与越权 | 两个合成 owner/integration、原文版本/指纹不符、伪 owner/scopes、旧候选晚到均拒绝或隔离，无内容泄漏/覆盖 |
| 持久幂等 | 重复送入、同 ID 内容冲突、重复确认、过时 revision、重启及创建版后回写前崩溃，确认映射仍唯一；实际数版本，不仅比响应ID |
| 来源真诚 | 原始声明与校对修订可追溯；提供方身份和自述模型/许可分开；缺失或未知不补造。旧 manual/synthetic 数据仍可读取/恢复 |
| 制品与文字修改 | 合法原创音频校验通过；损坏/hash/时锚错误不变可播；没有音频只部分可读；改英文后旧音频不静默沿用 |
| App 真链 | 同一候选列表/校对确认→真实学习列表→阅读；有音频才测原生暂停打开/播放/进度，冷启恢复。按钮/通知与后台实际状态一致 |
| 隐私/资源 | 默认不云调用/不开户/不自动TTS/不发布/不评分；无任意URL下载、私有路径与凭据输出；source/音频只留私有层，测试为原创材料 |
| 外部接入 | 受控发送端证据和真实助手工具调用证据分别留存；没有后一证据时明确“真实外部助手待验”，不让项目口头升级 |

完成流程：PM/架构评审小 Interface 与来源兼容→持久候选/确认事务与入口实现→独立 QA→App 有限原生/冷启验证→范围审计与功能分支交付；真实外部工具验证与本人产品验收按实际能力分别完成。内部代码通过不替代真实语言/音质效果验收。

## 7. 当前推进与真正缺口

可立即做：来源 Schema/兼容性、候选 Store Interface、事务与崩溃恢复、受限传输与 App 桥接、原创文本/合法已有素材的结构验证及失败路径。不需要现在开户、选择付费供应商或让用户定框架参数。

仍待证实：真实外部助手工具能力/可用连接、合法可用英语朗读音频、真实内容质量，以及现有账号/CLI/TTS 的使用范围和费用。不能假定免费或已授权；资源不足不自动创建账号、代用私有凭据，也不重复催开户。可读无音频与可听学习明确分开，专业评分仍单独准入。

核心候选→学习链验证后接回 PPTX，同入口完成后继续 PDF 成熟提取评审；已批准多格式目标保留。当前无必须用户立即决定的事项，团队先完成可审方案和无需账号的实现验证。
