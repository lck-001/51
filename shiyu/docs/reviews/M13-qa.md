# M13 媒体生命周期方案：独立 QA 评审

状态：方案评审；未执行新测试、未连接设备、未修改 App 逻辑。代码依据为仓库内 `validation/media-01/lib/main.dart`；以下矩阵是待验收项，不是通过清单。

## 评审结论

可进入状态与适配层详细设计，不能据此宣布后台播放已实现。验收目标：用户主动开始的音频在系统允许时可锁屏继续；用户暂停后不因生命周期或音频焦点回调自行恢复；视频进入后台默认暂停；采集进入后台应立即请求停止与释放，返回前台不自动重启。

当前代码与目标的差距：

- `main.dart:237` 的后台分支对所有媒体执行暂停，没有音频/视频策略区分，不能支持目标中的锁屏音频。
- `main.dart:28`、`:51`、`:62` 的播放器与事件订阅没有应用侧会话代次、用户播放意图、焦点恢复资格或系统媒体命令协调；`:382` 直接调用 `playOrPause()`。仅加后台播放插件不足以关闭竞态。
- `main.dart:84` 串行队列可避免部分并发调用，但后台清理可能被前序原生调用阻塞；没有清理时限、异常设备状态与紧急停止策略。
- `main.dart:117` 先清空相机引用再等待释放，释放异常后不能仅凭引用为空认定设备已关闭。`:251` 的清理路径中若 `_closeCamera()` 抛错，后续播放暂停会被跳过；各资源清理需独立尝试和记录结果。
- `main.dart:64` 在忙碌时忽略系统录音停止事件；`:188`、`:208`、`:231` 的异步开始/初始化完成后没有再次核对生命周期与所属会话。旧回调不能覆盖新会话，后台到达时也不能把刚完成的启动当作允许继续采集。
- `main.dart:387` 明示重启不恢复列表；现有内存状态不证明杀进程后的草稿、媒体索引或播放恢复能力。

## 有限验收矩阵

“纯状态”指后续以可控时钟、事件和假适配器验证逻辑；不代表本轮已编写或执行测试。原生能力必须补指定平台实机证据。

| 场景 | 静态/纯状态可核对 | 必须实机核对及预期 |
| --- | --- | --- |
| 主动音频锁屏 | 区分音频/视频；只有明确播放意图可保留播放；锁屏不创建新的自动播放授权 | 安卓锁屏及切后台，确认实际声音、时间轴、系统通知/控件；记录系统版本与省电条件 |
| 用户暂停与焦点恢复交错 | 暂停立即撤销恢复资格；暂停前已入队的恢复命令执行前重新检查；两种事件顺序均不自行播放 | 来电/其他音频结束、解锁、切前台后仍暂停；用户明确点系统播放可作为新的主动命令 |
| 瞬时与永久焦点丢失 | 瞬时丢失仅对同一会话保留有条件恢复资格；永久丢失撤销；duck 策略明确 | 实际音频竞争、耳机路由、通话打断；失焦策略依平台验证 |
| 新旧媒体会话回调 | A 切换到 B 后，A 的进度、错误、完成与焦点回调不得修改 B；事件携带会话代次 | 连续换文件、快速操作与系统命令交错，无串音、错误跳转或重复播放 |
| 视频后台暂停 | 后台事件撤销视频播放资格；前台返回不自动续播；系统播放命令是否允许须有明确策略 | 锁屏/切后台画面与声音均停止；不把只熄屏的音频伪装成视频通过 |
| 音频到录像/录音切换 | 采集前停止/暂停播放并关闭旧采集；失败时不偷偷恢复播放或换采集模式 | 录音/录像与播放互斥，采集文件无意外扬声器回录；实际路由另验 |
| 启动采集时切后台 | 初始化和 start 完成后再核对前后台与会话代次；过期成功须补偿停止/释放 | 权限弹窗、开始瞬间切后台、快速往返；返回后不自动开麦或开相机 |
| 停止/释放失败与超时 | stop、保存、相机释放、播放暂停独立收敛；不写假成功；保留失败/未知状态并限制再次采集 | 模拟可复现原生错误或故障设备；核对系统采集指示，不能仅看按钮或布尔值 |
| 系统主动停止录音 | 忙碌期间事件也被记录；结束状态幂等；文件未验证前不报保存成功 | 系统中断或撤权后 UI 与采集状态一致，返回前台需用户重新操作 |
| 系统媒体控件 | 播放/暂停/定位统一进入同一协调入口；旧通知命令拒绝；采集期间不启动播放 | 锁屏/通知/耳机按钮实际生效；控件显示、时间与 App 一致，无重复播放器 |
| 权限拒绝/撤销 | 区分麦克风与相机错误；拒绝不阻塞导入与播放；无权限不能进入采集中 | 首次拒绝、永久拒绝、设置撤权、权限对话框 inactive；不循环索权、不误启动设备 |
| 杀进程/冷启动恢复 | 恢复文件索引与恢复播放意图分离；默认不自动采集/播放；不把残留文件标为完整成功 | 进程被杀与正常关闭分别验证；断录文件可识别、无自动开麦；后台服务行为单列 |
| 重复后台及退出清理 | hidden/paused/detached 重复到达时清理幂等；dispose 不重启资源或更新已卸载 UI | 实际多次切换、关闭窗口/退出 App，无残留采集、重复保存或未处理异常 |

## 架构不得承诺的事项

1. 不承诺四个平台、所有机型或所有省电模式下后台音频永不中断；后台服务、音频会话、系统策略与权限需逐端证明。Windows 锁屏、睡眠和进程退出是不同场景。
2. 不承诺切后台后零毫秒停止采集或一定保存成功。应承诺立即提出停止请求、禁止自动重启、显式暴露失败；原生挂起、系统杀进程与写盘失败有真实边界。
3. 不把 `dispose()` 被调用、控制器引用为空、队列执行结束等同于硬件释放；不把解码成功等同于可懂度、专业发音评测或完整产品验收。
4. 不以静态审查、假适配器测试或已产出的 APK 替代 Android/iPhone/macOS 实机结论；不沿用其他设备的采集许可。
