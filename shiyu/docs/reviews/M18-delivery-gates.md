# M18：交付顺序与验收门槛

2026-11-18，交付产品经理核对。承接已批准 v0.13 与 M16/M17，不新增产品定位、平台或付费要求。本记录只根据当前源码、测试说明和已有验证记录划分阶段；未执行构建、设备、声音、云服务或人工验收。

## 1. 当前结论

**现在进入真实客户端与原生播放的应用组装，不能再把新增模块测试称为完整 App 交付。**

- `material_core`、`learning_core` 已有固定版本、实际落盘和续学位置能力；`learning_playback` 的独立 QA 记录为 22/22。
- `client_shell` 已有真实材料保存/确认、已有学习版阅读和紧凑词卡布局，含系统返回修复后的 Widget 测试为 12/12；正文→播放/进度→练习按钮→底部词卡的顺序保留。
- `client_runtime` 已连接真实 Shell 回调，最终独立持久集成测试为 9/9，分析无问题；用的是受控 Engine/System Adapter，不能据此宣称原生整 App 已运行。
- 原生播放验证仍在 `validation/playback-01`；其 Windows/Android 结果不能直接继承为新学习客户端通过。新应用组合后的初始化、文件解析、生命周期和退出必须再验。
- 三个新包已在独立 QA 修复并验收后提交至功能分支 `736dab1`；原生组装另批验证，不代表已分发或发布。
- 自动中文转英文、TTS、逐句音频对齐、真实专业发音评测、词典/词句本与复习、学习趋势、真实 Agent 接入和多格式上传尚未构成可用产品闭环。不能用空态或合成样例抵销这些需求。

## 2. 三种交付必须分开

| 候选 | 实际用途 | 达标条件 | 不能宣称 |
| --- | --- | --- | --- |
| C0 可安装工程候选 | 团队验证真实业务界面与原生播放组合 | 下节 G0—G3 通过；Windows 构建包与 Android 测试 APK 有版本/哈希/安装启动证据；界面可走真实保存和已有内容播放链 | 已能把任意中文材料自动变成学习包、已纠音、已四端完成、可向普通用户交付 |
| C1 个人体验候选 | 邀请本人按明确验收单体验核心价值 | G4—G6 的首条有限真实链通过，专业评分与无效录音拒评有证据；用户可从自己的已批准输入完成一次学习与复习，记录能恢复 | 多格式全支持、多人隐私隔离已投产、所有移动系统/OEM与 Apple 已验证 |
| C2 小范围试用候选 | 经人工验收后邀请身边人试用 | 真实账号/隔离/配额、反馈入口、必要运维与回退完成；涉及的平台分别有设备证据；人验通过后按独立灰度决策分发 | 正式全量上线、功能无缺陷、未验证平台已通过 |

C0 需要真实安装/启动证据；只生成文件时记录“已构建”。合成素材只可作为明确标识的测试内容，静音 WAV 只能验证结构/位置，不能用作“英语示范朗读”或证明音质。可安装不等于满足原始产品的完整交付要求。

### 第一条可学习内容如何进入

默认空库只能粘贴并保存材料，不能据此宣称“已可学习”。G1/G2 必须给出独立、可复现的内容装载路径和结果：工程测试可通过现有 MaterialStore/LearningStore 的固定版本与制品注册 Interface 装载原创手工双语及合法英语音频，再由真实 Shell 选中并走原生播放。来源标 manual/synthetic，句时锚、媒体长度/哈希须实校验，测试状态与私人数据隔离。

这符合 M16 已允许的合成/人工结构联调，不需要让用户重新确认技术方案；但只属于测试/调试装载，不等于已经存在面向用户的“手动配双语与音频编辑器”。不为填空库临时添加该新编辑器、不把测试装载默认作用于普通用户、不静默覆盖本机材料。没有真实英语朗读音频时只能记录结构验证，不能拿静音充当第一条能听的学习内容。

C1 的正常用户路径必须从自己的已确认输入进入真实内容任务，经处理状态到达可听可学的学习版本；如果仍只能靠工程师写入数据库/fixture，维持 C0，不称个人体验核心闭环完成。LLM/TTS 接口与任务处理可先准备，但缺资源不得把 seam、未执行请求或手写英文标作生成效果。

## 3. 本轮到后续的实际工作顺序

| --- | --- | --- | --- |

G4 的真实外部资源未就绪时，团队继续本地任务编排/失败恢复、G6 的存储与规则、G7 格式 Adapter 和 G8 隔离/运维准备，不以等账号为由停止其余工程。不得为“保持进展”制造假内容、假分数、假效果。

四端目标不变。Windows/Android 先有验证环境，不意味着删掉 iPhone/macOS；Apple 构建签名/设备和平台生命周期按能力到位后分别实证，不能从 Flutter 编译或 Android 成功推定通过。Android 真机暂缓仍按用户已有选择，不反复催连接。

## 4. 未接通能力在工程候选中的表达

| 用户操作 | 当前正确表达 | 不能出现的状态 |
| --- | --- | --- |
| 确认文字材料 | 原文已保存，学习内容尚未准备；显示真实草稿/固定版本 | “学习包生成成功”，实际只有原文 |
| 打开已有合成学习内容 | 明确标“合成示例”；播放器只显示真实观察状态 | 自动标为本人材料/AI翻译；无声素材标作英语朗读 |
| 点词 | 保留底部紧凑词卡；未接词典时明确不可查询，避免成功样式 | 编造音标/释义/例句、点击收藏却未落盘 |
| 跟读/复述 | 能力未接时清楚说明，不请求不必要权限 | 不录音就给分、把转写相似率标专业发音准确率 |
| 我的学习进步 | 只展示真实材料计数；学习/评测无有效数据用空态 | 演示 82 分、虚构学习天数/词量/增长趋势 |
| 分享与录像 | 尚未完成能力用可理解空态；已批准音频/视频方向保留 | 已发布、已同步第三方，但无实际回执 |

以上是工程阶段的诚实呈现，不等于批准永久缺失这些功能，也不作为一般用户可用性的验收替代。分享与添加仍分流，中心加号继续聚焦材料；不为工程演示塞入视频录制、语音输入和所有上传模式。

定向文案复核纳入 G0/G3：面向学习者的消息不使用“回执”“实际回执”“资源状态”等实现术语。改成用户可执行的含义，如“音频还没准备好”“暂时无法播放，请重试”“还没有评测结果”；保留必要的真实失败提示，诊断细节留本机工程记录。本批先列问题，由客户端后续定向修改并 QA，不与正在进行的源码改动并发。

## 5. 卡点由谁解决，何时才需要用户

内部技术选择、缓存/异步竞态、编译路径、包组合、日志归属、测试失败、原型一致性与普通范围内 Git 交付，由 PM/架构师/各端工程与 QA 解决；不让用户选框架或阅读 SDK 报错。

真正外部条件：

1. **真实 LLM/TTS/专业 Speech 的资源和数据/费用边界**：目前 Speech 只有免费准备方案，无可用账号资源，也无最终外发批准。团队必须先给具体可执行包，再请用户处理本人账号/身份/支付事项；不能代开服务、收聊天密钥或自动升级付费。现在不妨碍 G0—G3。
2. **真实设备与听说验收**：隐藏静音验证不能替代本人实听、专业纠音可理解性、真实手机/Apple 平台。待候选和步骤准备好后集中安排，按用户已有“安卓稍后测”执行；不反复索要设备。
3. **对外试用/灰度/正式上线**：内部专家通过只是技术准入，不能替代用户的人工验收和分发/发布决定。公开共享和站外自动代发不能由内部 QA 自动授权。

没有明确外部条件时不提问。批次验收通过后自动进入下一项，保留实际测试、评审和提交记录；会话/任务是否仍在运行按实时状态说明，不把“后台操作”写成 24 小时连续运行承诺。

## 6. 当前推进决定

现在执行 G0→G1→G2，先给团队一个真实可安装、可复验的工程候选，而不是继续单独扩展接口数量。G3 内部评审通过后，继续 G4—G8 的可独立工作；在 C1 条件具备时才集中请用户体验。当前没有必须由用户立即提供的决定或操作。

## 7. C0 主流程 P1：系统返回与未保存内容保护

原生安卓无窗口测试发现：添加页系统返回直接退出应用，阅读页返回也被应用级拦截当作退出。产品评审同意最小修复，不新增路由体系、不改变播放器归属。

- 阅读详情的系统返回与左上返回均回学习列表；页面返回不自动 Stop、不重建 Player，播放/进度沿已有协议。
- 新添加或校对页有未保存修改时，返回前确认：标题“放弃未保存的内容？”，正文“这次修改还没有保存，离开后将丢失。”，操作“继续编辑”与“放弃修改”。默认安全操作为继续编辑；取消保留输入与已保存数据，放弃只丢本次未保存修改，不删除草稿或固定版本，不自动保存/确认。
- 无未保存修改时返回此前的材料页面；无来源的新添加可回材料列表。其他主导航页先回学习根，只有学习根才调用应用拥有的退出处理。
- 保存/确认在途仍沿已有忙碌/防重协议，不得因返回重复提交或显示未持久化的成功；弹窗在途的重复返回不叠窗，按取消离开、继续编辑处理。
- Shell 只负责内部导航与退出意图，应用继续拥有 Stop、原生释放和关闭责任。独立 QA 验证系统返回、显式返回、放弃/取消、已保存草稿不丢和学习根退出，不能只验证按钮回调。

这是已批准材料编辑与学习流程的缺陷修复，无需新增用户产品决策；修复并回归通过前不进入 C0 验收。
